Part 1  A short zxnDDMA Primer
==============================================================================

1.1  Introduction
-----------------
A computer's picture, sound and programs are all numbers in memory.
To move a picture on the screen, play a sound or load a level, the
computer copies a great many of those numbers from one place to another.

On a ZX Spectrum the Z80 processor does all of this copying itself, one
byte at a time. While it copies, it can do nothing else. Its fastest
copying instruction, LDIR, takes 21 clock cycles for each byte.

1.2  What DMA is
----------------
DMA stands for Direct Memory Access. A DMA is a device
whose only job is copying. The Z80 tells it three things:

  - where to copy from,
  - where to copy to,
  - how many bytes.

Then the DMA takes over the computer's memory and does the copying
itself. With its usual settings it copies a byte in 6 clock cycles, and
at its fastest setting in 4. That is 3 to 5 times as fast as the Z80.

A useful comparison: the Z80 is a cook who also has to carry every plate
to the tables. The DMA is a waiter. The cook says "take these 20 plates
to table 6", and the waiter carries them while the cook gets on with
the next dish.

1.3  What a blitter is
----------------------
A blitter is a copying device made for pictures. The name comes from
"bit block transfer". The Commodore Amiga and the Atari STE are well
known for having one.

Like a DMA, a blitter copies memory without the processor. It also knows
about the shape of a picture. A blitter can:

  - copy a rectangle out of a larger picture, line by line;
  - leave out the background colour of a shape, so that what is behind
    it shows through;
  - fill an area with one colour;
  - (on some machines) shift a picture by a few pixels as it copies it,
    combine the old and the new pictures, or draw lines.

1.4  The zxnDMA
---------------
The zxnDMA is the Next's DMA. It is built into the Next's FPGA and is
based on the Zilog Z80 DMA chip of the 1980s. It has two modes:

  - port 0x6B: the zxnDMA's own mode;
  - port 0x0B: a mode that behaves like the original Zilog chip, for
    older programs written for it.

It can copy:

  - from memory to memory (for example, part of a picture to the screen);
  - from memory to a port (for example, sprite shapes to the sprite
    hardware, or sound samples to the sound output);
  - from a port to memory.

At each end the address can go up after each byte, go down after each
byte, or stay the same. "Stay the same" is what lets it feed a port:
every byte goes to the one port, one after another.

1.5  Timed copying, for sound
-----------------------------
The zxnDMA has a timer, called the prescaler. With it the DMA copies one
byte, waits, copies the next, and so on, at a steady rate. The rate is
875,000 divided by the prescaler value, in bytes a second. This is how
the Next plays sampled sound: the DMA sends one sample to the sound
output at each tick of the timer.

It has two ways of doing this:

  - continuous mode: the DMA keeps the memory until it has finished, and
    the Z80 waits;
  - burst mode: between bytes the DMA gives the memory back, so the Z80
    keeps running while the sound plays.

1.6  DMA+: the zxnDMA extension - The Next's blitter aka zxnDDMA
--------------------------------------------------------------------
In core 3.03.00 the zxnDMA is augmented by DMA+, which combined make it a
blitter. Its proper name is zxnDDMA for zxn D(imensional) DMA (since it knows
how to copy shapes). The zxnDMA from the previous iterations of the Spectrum
Next core is still a subset of the new system which means that everything that
worked before will keep on working now. The blitter-type work is done in the
zxnDDMA's own mode (port 0x6B), not in the Zilog mode.

  - All of the memory. The Z80 sees 64K at a time. The zxnDDMA can be given
    a full address in the Next's memory (command 0xD7 for one end, 0xDB
    for the other), so it can copy anywhere without the program first
    paging memory in.

  - Rectangles. Given a row length, a number of rows, and the distance
    from one row to the next at each end (commands 0xE3, 0xE7, 0xEB and
    0xEF), it copies a rectangle: for example a 32 by 32 picture out of a
    larger sheet of pictures, to a place on the screen.

  - A see-through colour. Given one colour (command 0xF3), it does not
    write the bytes of that colour. The background around a character
    is left out, and the screen behind it stays.

  - Fill. Given one value (command 0xF7), it writes that value over an
    area without reading anything. This clears or paints an area
    quickly.

  - Screen positions. Instead of a memory address, it can be given an X
    and a Y on the Layer 2 screen, in the 256 by 192 mode or the 320 by
    256 mode, and it works out the address itself.

  - The hidden screen. It can draw on the Layer 2 screen being shown, or
    on the second one that is not shown (nextreg 0x13). A game draws the
    next picture on the hidden screen, then swaps the two, so that the
    picture never shows half drawn.

Command 0xDF turns these on and off: full addresses, rectangles, the
see-through colour, fill, screen positions and the hidden screen.

1.7  Limitations
----------------
The zxnDDMA is a blitter with fewer functions than some other comparable
systems. It copies whole bytes, which on Layer 2 are whole pixels. It does not
shift a picture by part of a byte, combine the old and the new pictures, or
draw lines (other than straight ones).



==============================================================================
Part 2  Reference
==============================================================================

2.1  Overview
-------------
The zxnDMA is the Next's DMA. It is a single-channel DMA built into the
FPGA, and it does a subset of what the Zilog Z80 DMA (Z8410) does. The
subset is large enough for the common uses of the Datagear interface for
the standard ZX Spectrum.

The zxnDDMA is the zxnDMA with the extra commands of DMA+ (see primer above):
24-bit addresses, rectangles, a transparent colour, fill, and Layer 2 X,Y
positions. Every 3.03.00 build has it: issue 2 (Spartan6-SLX16), issue 4 and
issue 5 (Artix A7-15T and A7-35T respectively).
The sources that describe how it works on the hardware level are located in
cores/zxnext/src/device/new_dma.vhd.
In short, everything the zxnDMA did before still works the same way with
additional functionality.

It answers on two ports:

  $6B  zxnDMA mode. All the commands in this part.
  $0B  Z80 DMA mode, which behaves like the Zilog chip for older programs.
       The commands of 2.5 are ignored here.

The commands below use OUT (C),A with BC = $006B. OUT ($6B),A works too:
the port is decoded on A7-A0 only.

The Zilog chip is pipelined, and so has a number of off-by-one quirks and
rules on the order of its commands. The zxnDMA does not have these. It
can be programmed as a Z8410, or in the simpler way shown here.

The DMA has two ports, A and B. A transfer goes from A to B or from B to
A. Each port is memory or I/O, and after each byte its address goes up,
goes down, or stays the same.


2.2  How the registers are written
----------------------------------
There are seven write register groups, WR0 to WR6. There is no separate
"select the register" write: each byte written to the port is matched
against the bit patterns below, and the remaining bits are the data.

Some bits of a base byte say that more bytes follow. The next bytes then
go to those registers, in the order of their bits from right to left
(D0 first). After the last of them the DMA expects a new base byte.

The patterns do not overlap, so a byte selects at most one group. A byte
with bit 7 = 1 and bits 1:0 = 10 that does not match WR5 is ignored.

  Group  Pattern   What it sets
  -----  --------  ---------------------------------------------
  WR0    0xxxxxAA  direction, Port A address, block length
                   (AA must not be 00)
  WR1    0xxxx100  Port A
  WR2    0xxxx000  Port B
  WR3    1xxxxx00  enable (WR6 $87 is the better way)
  WR4    1xxxxx01  mode, Port B address
  WR5    10xxx010  stop or restart at the end
  WR6    1xxxxx11  commands


2.3  The registers, WR0 to WR6
------------------------------

WR0  Transfer setup
  Pattern: bit 7 = 0, and bit 1 = 1 or bit 0 = 1

  Byte 0HLhlDTT
    bit 6    H  block length high byte follows
    bit 5    L  block length low byte follows
    bit 4    h  Port A address high byte follows
    bit 3    l  Port A address low byte follows
    bit 2    D  direction: 0 = B to A, 1 = A to B
    bits 1:0 TT transfer: 01 (10 and 11 also act as 01; 00 is not WR0)

  Each follow bit is on its own. Bit 4 without bit 3 loads only the high
  byte of the Port A address, and the low byte stays as it was. For a full
  16-bit address set both bits 3 and 4; the same goes for bits 5 and 6.

  Follow bytes, one for each bit set, in this order:
    1. Port A address low   (bit 3)
    2. Port A address high  (bit 4)
    3. Block length low     (bit 5)
    4. Block length high    (bit 6)

  Common values:
    $7D  A to B, Port A address and block length follow (4 bytes)
    $79  B to A, Port A address and block length follow
    $1D  A to B, Port A address only (the short reload, note 1)

WR1  Port A
  Pattern: bit 7 = 0, bits 2:0 = 100

  Byte 0TMMP100
    bit 6    T  timing byte follows
    bits 5:4 MM address: 00 down, 01 up, 10 or 11 fixed
    bit 3    P  0 = memory, 1 = I/O

  Timing byte --P---TT
    bits 1:0 TT cycle length: 00 = 4, 01 = 3, 10 = 2, 11 = 4
    bit 5    P  one more byte follows. On WR1 it is read and ignored:
                only Port B has a prescaler.

  Common values:
    $14  memory, up, no timing byte
    $24  memory, fixed (the source of a fill)
    $2C  I/O, fixed
    $54  memory, up, timing byte follows

WR2  Port B
  Pattern: bit 7 = 0, bits 2:0 = 000

  Byte 0TMMP000, the same layout as WR1.

  Follow bytes, if bit 6 = 1:
    Timing byte, the same layout as WR1.
    Prescaler, if bit 5 of the timing byte = 1 (2.7).

  Common values:
    $10  memory, up, no timing byte
    $28  I/O, fixed
    $68  I/O, fixed, timing byte follows

WR3  Enable
  Pattern: bit 7 = 1, bits 1:0 = 00

  Bit 6 = 1 starts the DMA at once, like $87. Bit 3 and bit 4 each say
  that a byte follows (mask, then match). Both are read and ignored, as
  there is no search. WR6 $87 is the better way to start the DMA.

WR4  Mode and Port B address
  Pattern: bit 7 = 1, bits 1:0 = 01

  Byte 1MMIHL01
    bit 7    must be 1: $2D, with bit 7 = 0, is read as WR0
    bits 6:5 MM mode: 00 byte, 01 continuous, 10 burst
                (byte acts as continuous)
    bit 4    I  interrupt control byte follows. Not there: keep it 0.
    bit 3    H  Port B address high byte follows
    bit 2    L  Port B address low byte follows

  Bit 4 with bits 3:2 = 00 (for example $91, $B1, $D1) hangs the register
  decoder. It waits for an interrupt control byte it has no handler for,
  and takes no more DMA programming until the next reset. When bit 2 or
  bit 3 is also set, bit 4 is skipped and does no harm.

  Follow bytes, in this order:
    1. Port B address low   (bit 2)
    2. Port B address high  (bit 3)

  Common values:
    $AD  continuous, Port B address follows (2 bytes)
    $CD  burst, Port B address follows (2 bytes)
    $A1  continuous, no address bytes
    $C1  burst, no address bytes

  Modes:
    Continuous: the DMA keeps the memory until the transfer has finished.
    The Z80 waits.
    Burst: when a prescaler is set, the DMA gives the memory back to the
    Z80 while it waits between bytes, and the Z80 runs.

WR5  End of block
  Pattern: bits 7:6 = 10, bits 2:0 = 010

  Byte 10AWR010
    bit 5    A  0 = stop at the end of the block, 1 = start it again
    bit 4    W  CE/WAIT multiplexed: kept, no effect (WAIT is always used)
    bit 3    R  READY active level: ignored

  With auto restart the DMA loads its start addresses again, sets its
  byte counter to 0, and does the same transfer again.

  Common values:
    $82  stop at the end of the block
    $B2  start again (loop)

WR6  Commands
  Pattern: bit 7 = 1, bits 1:0 = 11. See 2.4 and 2.5.


2.4  WR6 commands
-----------------
  $C3  Reset: clears the settings of 2.6
  $C7  Port A timing back to 3 cycles
  $CB  Port B timing back to 3 cycles
  $CF  Load: copies the WR0 and WR4 start addresses (and the $D7 and $DB
       bytes) to the working addresses, and resets the counters
  $D3  Continue: resets the byte counter but keeps the working
       addresses, so the next $87 carries on from where the last
       transfer ended
  $87  Enable: starts the transfer
  $83  Disable: stops the transfer
  $8B  Reinitialise the status byte
  $A7  Start the read sequence
  $BB  Read mask follows (1 byte)
  $BF  Read the status byte

  These are taken and do nothing (there are no interrupts or READY):
  $A3 reset and disable interrupts, $AB enable interrupts, $AF disable
  interrupts, $B3 force ready, $B7 enable after RETI.

  Other Z80 DMA commands are ignored.

  Reading back
    After the read mask is set ($BB), each IO read of the port returns
    the next register the mask selects, in this order:

      bit 0  status byte
      bit 1  byte counter low
      bit 2  byte counter high
      bit 3  Port A address low
      bit 4  Port A address high
      bit 5  Port B address low
      bit 6  Port B address high

    The values are the working values: "Port A address low" is the low
    byte of the next Port A address. After the last one the reads start
    again at the first. At power up the read mask is $7F.


2.5  zxnDDMA commands (port $6B only)
-------------------------------------
These commands are ignored on port $0B. Their follow bytes are not: on
port $0B, and on a core without the zxnDDMA, the command byte is dropped
and the bytes after it are read as ordinary register writes. Software
that must also run on such cores finds out first whether the zxnDDMA is
there (3.4, zxnddma_compare.asm, shows a safe way).

Full addresses
  $D7 nn  Port A address bits 23:16
  $DB nn  Port B address bits 23:16

  The physical address is {extended bits 5:0, start address 15:0}, 22
  bits. Bits 7:6 of the extended byte are dropped. How much of the range
  is there depends on the board's SRAM:

    Issue 5  4 MB  $000000-$3FFFFF
    Issue 4  2 MB  $000000-$1FFFFF (bit 21 is dropped: higher addresses
                   wrap)
    Issue 2  1 MB  $000000-$0FFFFF, or $1FFFFF with the 2 MB expansion

  A 16K RAM bank is at $40000 + bank x $4000 (bank 0 at $40000). Banks 5
  and 7 are in block RAM, so a physical transfer to their SRAM addresses
  does not reach the ULA screen. Use ordinary (MMU) addresses for them.

Mode flags
  $DF mm [X_lo X_hi Y]   1 byte, and 3 more when bit 4 is set

    bit 0  physical: 22-bit SRAM addresses, no MMU
    bit 1  2D: rows, with the row length, number of rows and strides
    bit 2  transparent: a source byte equal to the $F3 colour is not
           written
    bit 3  fill: no read; the $F7 value is written. Twice as fast as a
           fixed source address.
    bit 4  Layer 2 X,Y: 3 bytes follow, and the Port B address is worked
           out from them. Port B stride becomes 256. Needs bit 0 too.
    bit 5  hidden screen: with bit 4, use the bank in nextreg $13 in
           place of $12. Ignored without bit 4.
    bits 7:6  write 0

  Each $DF sets every flag at once, so send the whole set, not only the
  bit that changes.

Layer 2 X,Y ($DF bit 4)
  The Port B address is worked out from the Layer 2 bank (nextreg $12, or
  $13 with bit 5) and the mode in nextreg $70 bits 5:4. It writes the
  Port B start address (WR4) and the Port B extended address ($DB).

    $70 mode  Screen   Address
    00        256x192  base + Y x 256 + X (row by row)
    01        320x256  base + X x 256 + Y (column by column)
    10        640x256  base + X x 256 + Y (X is the byte column, 0-319)
    11        -        as 01

  base = $40000 + bank x $4000.

  - Bit 0 (physical) must be set too. The address is a physical one;
    without bit 0 its low 16 bits go through the MMU like any other.
  - The Port B stride is set to 256 and stays so after the transfer,
    until $EF or $C3. The source stride is still set with $EB, and bit 1
    (2D) still set for a rectangle.
  - In the column modes a 2D "row" runs down a screen column, as the 256
    stride steps to the next X. There, the row length is the rectangle's
    height, the number of rows its width, and the source is stored column
    by column.
  - Send $DF with bit 4 after WR4, or use a WR4 with no address bytes
    ($A1 or $C1): a WR4 with a Port B address overwrites the worked-out
    one.
  - In mode 00 only X_lo is added; X_hi is read and ignored. Send X_hi =
    0. In the column modes only bit 0 of X_hi is used (the column number
    is 9 bits).

Rectangles
  $E3 ll hh  row length: bytes in each row
  $E7 ll hh  number of rows
  $EB ll hh  Port A stride: the source's distance between rows
  $EF ll hh  Port B stride: the destination's distance between rows

  All are 16 bits, low byte first. A stride is the distance from the
  start of one row to the start of the next, not the gap after a row. It
  is added to the row's 24-bit start address, so in physical mode rows
  can cross 64K boundaries.

  In 2D mode the block length (WR0) is not used. The DMA moves row length
  x number of rows bytes. A row length or number of rows of 0 still moves
  one byte.

Transparent colour
  $F3 nn  the transparent colour

  With $DF bit 2, a byte equal to this value is not written. Both
  addresses still move on. This is for drawing shapes with see-through
  parts.

Fill value
  $F7 nn  the fill value

  With $DF bit 3, the DMA does no reads. Every destination byte gets the
  fill value.

$FB
  An earlier version had $FB (copy the hidden Layer 2 screen to the shown
  one). It is commented out in new_dma.vhd, and the byte is ignored.


2.6  What $C3 Reset clears
--------------------------
  Transfer             stopped
  Port A timing        3 cycles
  Port B timing        3 cycles
  Port B prescaler     0
  CE/WAIT              off
  Auto restart         off
  Physical, 2D,
  transparent, fill    off
  Hidden screen flag   off
  $D7 and $DB bytes    $00
  Row length, number
  of rows, strides     0
  Transparent colour   $00
  Fill value           $00

  $C3 does not change the Port A and B start addresses (WR0, WR4), the
  direction, port types, address modes, transfer mode, block length or
  read mask.


2.7  Timing and speed
---------------------
The cycle length (WR1, WR2) is how many clock cycles one read or one
write takes. The first cycle sets the signals and the last one releases
them. After $C3 both ports use 3 cycles, so a byte takes 6. At the
fastest setting, 2 and 2, it takes 4.

The prescaler (WR2) makes each byte take a fixed time, so the DMA can
play sampled sound. The rate is 875 kHz / prescaler, in bytes a second,
at every CPU speed (the timer allows for the turbo). 0 means no
prescaler. It works in both continuous and burst mode. In burst mode the
Z80 runs while the DMA waits between bytes.


2.8  A typical transfer
-----------------------
    DMA_OUT $C3      ; 1. reset
    ; 2. $D7 and $DB, for physical addresses
    ; 3. $DF: physical, 2D, transparent, fill
    ;    (with bit 4, Layer 2 X,Y: send $DF after step 10)
    ; 4. $E3, $E7, $EB, $EF, for 2D
    ; 5. $F3, for transparent
    ; 6. $F7, for fill
    ; 7. WR0: direction, source address, block length
    ; 8. WR1: Port A (memory or I/O, up, down or fixed, timing)
    ; 9. WR2: Port B
    ; 10. WR4: mode (continuous or burst), destination address
    ;     (a Layer 2 X,Y $DF goes here, or WR4 has no address bytes)
    ; 11. WR5 if needed: $82 stop, $B2 start again
    DMA_OUT $CF      ; 12. load
    DMA_OUT $87      ; 13. enable


2.9  Important notes
--------------------
 1. Settings stay until $C3: WR1, WR2, WR5, the 2D values, the
    transparent and fill values and the mode flags. Send $C3 before a
    different kind of transfer, so that a fill or transparent flag left
    on does not apply. Many copies of one shape need only a short reload
    (checked on an issue 5, 2026-10-20): $1D lo hi (WR0, Port A address
    only), then for a Layer 2 destination $DF flags xlo xhi y, otherwise
    $AD lo hi, then $CF $87. Add $D7 hi when the source moves to another
    64K.
 2. WR4 bit 7 must be 1: $AD (continuous), $CD (burst). $2D is WR0.
 3. WR6 commands end in binary 11. A byte whose bits 1:0 are not 11 is
    not a WR6 command.
 4. $CF (load) is needed. Without it the addresses of the last transfer
    are used.
 5. Physical addresses are 22 bits. The DMA puts out a full 8-bit high
    byte, but the SRAM selection in zxnext.vhd takes only its bits 5:0,
    so bits 7:6 of the extended byte are dropped. 22 bits are 4 MB; issue
    4 has 2 MB and issue 2 has 1 or 2 MB (2.5).
 6. Block length: on port $6B a length of N (1 or more) moves N bytes. On
    port $0B it moves N+1, as a Z80 DMA does, so $FFFF moves 65536. A
    length of $0000 moves 1 byte on both (the first byte goes before the
    length is checked). In 2D mode the block length is not used.
 7. In physical mode an address going up carries from the low 16 bits
    into the extended byte at $FFFF, and one going down borrows at $0000.
    Outside physical mode the address wraps within 64K.
 8. WR4 bit 4 must be 0 (2.3, WR4).
 9. Physical mode stays on until the next $DF or $C3. A later transfer
    that uses MMU addresses must turn it off.
10. Hardware IM2 can hold the DMA back. With hardware IM2 on (nextreg
    $C0 bit 0) and an interrupt source chosen in nextregs $CC-$CE, the
    DMA waits while that interrupt is pending. Under DI a pending
    interrupt is never taken, so a transfer started then never runs.
    Clear the $CC-$CE bits, or keep interrupts on, around such a
    transfer. (Seen on an issue 5, 2026-10-21.)

3.1  zxndma_example.asm
-----------------------
The zxnDMA on its own: a copy to the screen, a sprite shape to sprite RAM, and
a fill (by Jim Bagley).

;------------------------------------------------------------------------------
device zxspectrum48
;------------------------------------------------------------------------------
; DEFINE testing
;------------------------------------------------------------------------------
; DMA (Register 6)
;
;------------------------------------------------------------------------------
;zxnDMA programming example
;------------------------------------------------------------------------------
;(c) Jim Bagley
;------------------------------------------------------------------------------
DMA_RESET                      equ $c3
DMA_RESET_PORT_A_TIMING        equ $c7
DMA_RESET_PORT_B_TIMING        equ $cb
DMA_LOAD                       equ $cf ; %11001111
DMA_CONTINUE                   equ $d3
DMA_DISABLE_INTERUPTS          equ $af
DMA_ENABLE_INTERUPTS           equ $ab
DMA_RESET_DISABLE_INTERUPTS    equ $a3
DMA_ENABLE_AFTER_RETI          equ $b7
DMA_READ_STATUS_BYTE           equ $bf
DMA_REINIT_STATUS_BYTE         equ $8b
DMA_START_READ_SEQUENCE        equ $a7
DMA_FORCE_READY                equ $b3
DMA_DISABLE                    equ $83
DMA_ENABLE                     equ $87
DMA_WRITE_REGISTER_COMMAND     equ $bb
DMA_BURST                      equ %11001101
DMA_CONTINUOUS                 equ %10101101
ZXN_DMA_PORT                   equ $6b
SPRITE_STATUS_SLOT_SELECT      equ $303B
SPRITE_IMAGE_PORT              equ $5b
SPRITE_INFO_PORT               equ $57
;------------------------------------------------------------------------------

    IFDEF testing
        org $6000
    ELSE
        org $2000
    ENDIF

start
    ld   hl,$0000
    ld   de,$4000
    ld   bc,$800
    call TransferDMA                  ; copy some random data to the screen pointing
                                      ; to ROM for now, for the purpose of showing
                                      ; how to do a DMA copy.
    ld   a,0                          ; sprite image number we want to update
    ld   bc,SPRITE_STATUS_SLOT_SELECT
    out  (c),a                        ; set the sprite image number
    ld   bc,1*256                     ; number to transfer (1)
    ld   hl,testsprite                ; from
    call TransferDMASprite            ; transfer to sprite ram

    nextreg 21,1                      ; turn sprite on. for more info on this check
                                      ; out https://www.specnext.com/tbblue-io-port-system/
    ld   de,0
    ld   (xpos),de                    ; set initial X position ( doesn't need it for
                                      ; this demo, but if you run the .loop again it
                                      ; will continue from where it was
    ld   a,$20
    ld   (ypos),a                     ; set initial Y position

.loop
    ld   a,0                          ; sprite number we want to position
    ld   bc,SPRITE_STATUS_SLOT_SELECT
    out  (c),a

; =============================================================================
; zxnDDMA Extended Features - Reference Examples
; Core 3.03.00, all boards (issue 2, 4 and 5 builds all include zxnDDMA)
; Demonstrates 22-bit physical addressing and 2D stride transfers.
; The zxnDDMA commands themselves are checked on hardware by NextTestSuite
; (issue 2 and issue 5, 2026-10-20); these listings are reference code.
; Full command reference: /docs/zxnDDMA/zxnddma.gde
;
; New ZXN DMA commands (port $6B only, ZXN mode):
;   $D7, <byte>       - Set Port A extended address [23:16]
;   $DB, <byte>       - Set Port B extended address [23:16]
;   $DF, <byte>       - Set mode flags (all at once, send the full set):
;                         bit 0 = physical addressing (bypasses MMU)
;                         bit 1 = 2D stride mode
;                         bit 2 = transparent skip (colour set by $F3)
;                         bit 3 = fill (value set by $F7, no read phase)
;                         bit 4 = Layer 2 X,Y destination, 3 more bytes
;                                 (X_lo, X_hi, Y); needs bit 0 as well
;                         bit 5 = with bit 4, use the shadow bank (NR $13)
;   $E3, <lo>, <hi>   - Set row length (bytes per row to transfer)
;   $E7, <lo>, <hi>   - Set number of rows
;   $EB, <lo>, <hi>   - Set Port A stride (pitch between row starts)
;   $EF, <lo>, <hi>   - Set Port B stride (pitch between row starts)
;   $F3, <byte>       - Set transparent colour
;   $F7, <byte>       - Set fill value
;
; Physical addressing mode:
;   The DMA module emits a 24-bit address per port (extended byte + 16-bit
;   start address), but the SRAM mux in zxnext.vhd routes only the low 22
;   bits: {extended[5:0], start_addr[15:0]} -> 4MB physical SRAM space.
;   Bits [7:6] of the extended byte are silently dropped. Issue 5 has 4MB,
;   issue 4 has 2MB and issue 2 has 1MB or 2MB; above that, addresses wrap.
;   Physical mode bypasses the MMU entirely; reads always come from SRAM,
;   never BRAM (so banks 5 and 7 are not reachable this way).
;
; 2D stride mode:
;   Transfers row_length bytes, then advances both source and destination
;   by their respective strides. Repeats for num_rows.
;   Stride = pitch = distance between the START of consecutive rows,
;   NOT the gap after each row.
;
; IMPORTANT NOTES:
;   1. R4 register byte MUST have bit 7 = 1:
;      $AD = continuous mode (CPU blocked during transfer)
;      $CD = burst mode (CPU runs during prescaler waits - use for audio!)
;      $2D is WRONG - bit 7=0 will be silently parsed as R0!
;
;   2. The examples use OUT (C),A with BC = $006B. The DMA port is decoded
;      on A7-A0 only, so OUT ($6B),A works just as well.
;
;   3. Layer 2 default base in NextZXOS is bank 9 (physical 0x064000),
;      NOT the hardware default bank 8 (0x060000).
;
;   4. R5 stop/restart control:
;      $82 = stop on end of block (DMA halts after transfer completes)
;      $B2 = auto-restart (loops back to start address and repeats)
;
;   5. For burst mode audio playback, the prescaler (R2 follow byte)
;      controls the sample rate: 875kHz / prescaler, at any CPU speed
;      (the DMA's timer is compensated for turbo).
;      prescaler 109 ~ 8kHz, 55 ~ 16kHz, 27 ~ 32kHz
; =============================================================================

ZXN_DMA_PORT    equ $6B         ; ZXN DMA native mode port

; Helper macro: output A to DMA port via OUT (C),A
; Assumes BC = ZXN_DMA_PORT (set once at start of each example)
    macro DMA_OUT val
        ld a, val
        out (c), a
    endm

; -----------------------------------------------------------------------------
; Example 1: 24-bit Physical Memory Copy
;
; Copy 4096 bytes from physical address 0x040000 to physical address 0x064000.
;
; In physical mode the full 24-bit address is:
;   extended[7:0] = bits 23:16
;   start_addr[15:0] = bits 15:0
;
; So 0x040000 = extended 0x04, start 0x0000
;    0x064000 = extended 0x06, start 0x4000
; -----------------------------------------------------------------------------

example_phys_copy:

    ld bc, ZXN_DMA_PORT

    ; --- Reset DMA ---
    DMA_OUT $C3

    ; --- Set extended address bytes (bits 23:16) ---
    DMA_OUT $D7                 ; Set Port A extended addr command
    DMA_OUT $04                 ; Port A addr[23:16] = 0x04

    DMA_OUT $DB                 ; Set Port B extended addr command
    DMA_OUT $06                 ; Port B addr[23:16] = 0x06

    ; --- Enable physical addressing mode ---
    DMA_OUT $DF                 ; Set mode flags command
    DMA_OUT %00000001           ; bit 0 = physical mode ON, bit 1 = 2D OFF

    ; --- Program standard DMA registers ---

    ; Register 0: direction A->B, Port A start address, block length
    DMA_OUT %01111101           ; R0: A->B, addr follows, length follows
    DMA_OUT $00                 ; Port A addr[7:0]  = 0x00
    DMA_OUT $00                 ; Port A addr[15:8] = 0x00
    DMA_OUT $00                 ; Block length[7:0] = 0x00  (4096 = 0x1000)
    DMA_OUT $10                 ; Block length[15:8] = 0x10

    ; Register 1: Port A is memory, increment
    DMA_OUT %00010100           ; R1: memory, increment, no follow byte

    ; Register 2: Port B is memory, increment
    DMA_OUT %00010000           ; R2: memory, increment, no follow byte

    ; Register 4: continuous mode, Port B start address
    DMA_OUT $AD                 ; R4: continuous, port B addr follows
                                ; bit 7 = 1 is REQUIRED for R4!
    DMA_OUT $00                 ; Port B addr[7:0]  = 0x00
    DMA_OUT $40                 ; Port B addr[15:8] = 0x40

    ; --- Load and start ---
    DMA_OUT $CF                 ; Load command (initializes counters)
    DMA_OUT $87                 ; Enable DMA (starts transfer)

    ; DMA runs autonomously; CPU resumes after transfer completes.
    ret


; -----------------------------------------------------------------------------
; Example 2: 2D Stride Blit (Rectangle to Layer 2)
;
; Copy a 32x24 pixel rectangle from a source sprite sheet to Layer 2.
;
; Source: physical 0x050000, sprite sheet is 128 bytes wide
;   - row length = 32 bytes, stride (pitch) = 128 bytes
;
; Destination: Layer 2 bank 9 at physical 0x064000 + offset (100,50)
;   - dest addr = 0x064000 + (50 * 256) + 100 = 0x067264
;   - row length = 32 bytes, stride (pitch) = 256 bytes (screen width)
;
; Transfer: 32 bytes per row, 24 rows
; Total: 768 bytes blitted as a rectangle, not a linear block.
; -----------------------------------------------------------------------------

example_2d_blit:

    ld bc, ZXN_DMA_PORT

    ; --- Reset DMA ---
    DMA_OUT $C3

    ; --- Set extended address bytes ---
    DMA_OUT $D7                 ; Port A extended addr
    DMA_OUT $05                 ; Source at 0x05xxxx

    DMA_OUT $DB                 ; Port B extended addr
    DMA_OUT $06                 ; Dest at 0x06xxxx (Layer 2 bank 9)

    ; --- Enable physical + 2D stride mode ---
    DMA_OUT $DF                 ; Set mode flags
    DMA_OUT %00000011           ; bit 0 = physical, bit 1 = 2D stride

    ; --- Set 2D parameters ---

    ; Row length = 32 bytes
    DMA_OUT $E3                 ; Set row length command
    DMA_OUT 32                  ; row_len[7:0]
    DMA_OUT 0                   ; row_len[15:8]

    ; Number of rows = 24
    DMA_OUT $E7                 ; Set num rows command
    DMA_OUT 24                  ; num_rows[7:0]
    DMA_OUT 0                   ; num_rows[15:8]

    ; Port A stride (source pitch) = 128 bytes
    DMA_OUT $EB                 ; Set Port A stride command
    DMA_OUT 128                 ; stride_A[7:0]
    DMA_OUT 0                   ; stride_A[15:8]

    ; Port B stride (dest pitch) = 256 bytes
    DMA_OUT $EF                 ; Set Port B stride command
    DMA_OUT 0                   ; stride_B[7:0]  (256 = 0x0100)
    DMA_OUT 1                   ; stride_B[15:8]

    ; --- Standard DMA registers ---

    ; R0: A->B, Port A start = 0x0000 (low 16 bits of 0x050000)
    DMA_OUT %01111101
    DMA_OUT $00                 ; Port A addr[7:0]
    DMA_OUT $00                 ; Port A addr[15:8]
    ; Block length is ignored in 2D mode, but R0 bits 5/6 are set so
    ; the follow bytes must still be present
    DMA_OUT $00                 ; Block length (don't care in 2D)
    DMA_OUT $00

    ; R1: Port A = memory, increment
    DMA_OUT %00010100

    ; R2: Port B = memory, increment
    DMA_OUT %00010000

    ; R4: continuous mode, Port B start = 0x7264 (low 16 bits of dest)
    DMA_OUT $AD                 ; bit 7 = 1 REQUIRED for R4!
    DMA_OUT $64                 ; Port B addr[7:0]
    DMA_OUT $72                 ; Port B addr[15:8]

    ; --- Load and go ---
    DMA_OUT $CF                 ; Load
    DMA_OUT $87                 ; Enable DMA

    ret


; -----------------------------------------------------------------------------
; Example 3: 2D Fill (clear Layer 2 to a fixed colour)
;
; Fill the 256x192 Layer 2 screen at physical 0x064000 with the value
; stored at physical 0x090000 (a single byte poked via SPI or CPU).
;
; Checked on an issue 5 (3.02.21, 2026-10-21): every byte of $064000-$06FFFF
; became the colour, with the bytes either side untouched.
;
; Uses Port A with fixed address mode (reads the same byte every time)
; and Port B incrementing with stride = 256 (screen width).
;
; zxnDDMA fill mode does the same job faster and needs no source byte:
; $DF with bit 3 set, the colour sent with $F7, and no read phase at all.
;
; row_len = 256, num_rows = 192, dest stride = 256.
; Total: 49152 bytes (full Layer 2 screen).
; -----------------------------------------------------------------------------

example_2d_fill:

    ; Assume the fill colour byte has been written to physical 0x090000.

    ld bc, ZXN_DMA_PORT

    DMA_OUT $C3                 ; Reset

    ; Extended addresses
    DMA_OUT $D7
    DMA_OUT $09                 ; Port A: physical 0x09xxxx (fill source)

    DMA_OUT $DB
    DMA_OUT $06                 ; Port B: physical 0x06xxxx (Layer 2 bank 9)

    ; Mode: physical + 2D
    DMA_OUT $DF
    DMA_OUT %00000011

    ; 2D params: 256 bytes/row, 192 rows
    DMA_OUT $E3
    DMA_OUT 0                   ; row_len = 256 (0x0100)
    DMA_OUT 1

    DMA_OUT $E7
    DMA_OUT 192                 ; 192 rows
    DMA_OUT 0

    DMA_OUT $EB                 ; Port A stride (irrelevant, addr is fixed)
    DMA_OUT 0
    DMA_OUT 0

    DMA_OUT $EF                 ; Port B stride = 256
    DMA_OUT 0
    DMA_OUT 1

    ; R0: A->B, Port A start = 0x0000 (low 16 of 0x090000)
    DMA_OUT %01111101
    DMA_OUT $00                 ; Port A addr[7:0]
    DMA_OUT $00                 ; Port A addr[15:8]
    DMA_OUT $00                 ; block len (ignored in 2D)
    DMA_OUT $00

    ; R1: Port A = memory, FIXED address (reads same byte each time)
    DMA_OUT %00100100           ; memory (bit 3 = 0), fixed (bits 5:4 = 10)

    ; R2: Port B = memory, increment
    DMA_OUT %00010000

    ; R4: continuous, Port B addr = 0x4000 (low 16 bits of 0x064000)
    DMA_OUT $AD                 ; bit 7 = 1 REQUIRED for R4!
    DMA_OUT $00
    DMA_OUT $40

    DMA_OUT $CF                 ; Load
    DMA_OUT $87                 ; Enable

    ret


; -----------------------------------------------------------------------------
; Example 4: Background Audio Playback (burst mode)
;
; Play 527KB of 8-bit unsigned PCM audio from physical 0x0E0000 (bank $28)
; to the SpecDrum DAC port ($FFDF) using burst mode. The CPU returns to
; BASIC immediately and remains usable while audio plays in the background.
;
; Uses 2D stride to handle >64KB of data:
;   row_len = 2061, num_rows = 256 -> 527616 bytes total
;   Source stride = row_len (linear data, no gaps)
;   Dest stride = 0 (I/O port, doesn't advance)
;
; The prescaler controls playback speed, at any CPU speed:
;   875kHz / 55 ~ 16kHz sample rate
;
; Burst mode ($CD for R4) releases the bus during prescaler waits,
; allowing the CPU to run. Continuous mode ($AD) would block the CPU.
;
; Stop playback early with: OUT 107,131  (port $6B, value $83)
; For looping: change R5 from $82 (stop) to $B2 (auto-restart)
; -----------------------------------------------------------------------------

SPECDRUM         equ $FFDF
PRESCALER        equ 55          ; ~16kHz (875kHz / 55)

example_audio_playback:

    ld bc, ZXN_DMA_PORT

    DMA_OUT $C3                 ; Reset

    ; Source: physical 0x0E0000 (bank $28)
    DMA_OUT $D7
    DMA_OUT $0E                 ; Port A extended = 0x0E

    DMA_OUT $DB
    DMA_OUT $00                 ; Port B extended (don't care for I/O)

    ; Physical + 2D stride
    DMA_OUT $DF
    DMA_OUT %00000011

    ; 2D params: 2061 bytes/row, 256 rows = 527616 bytes
    DMA_OUT $E3
    DMA_OUT 2061 & $FF          ; row_len lo = $0D
    DMA_OUT 2061 >> 8           ; row_len hi = $08

    DMA_OUT $E7
    DMA_OUT 256 & $FF           ; num_rows lo = $00
    DMA_OUT 256 >> 8            ; num_rows hi = $01

    DMA_OUT $EB                 ; Port A stride = row_len (linear data)
    DMA_OUT 2061 & $FF
    DMA_OUT 2061 >> 8

    DMA_OUT $EF                 ; Port B stride = 0 (I/O port)
    DMA_OUT 0
    DMA_OUT 0

    ; R0: A->B, Port A start = 0x0000 (low 16 of 0x0E0000)
    DMA_OUT %01111101
    DMA_OUT $00
    DMA_OUT $00
    DMA_OUT $00                 ; block len (ignored in 2D)
    DMA_OUT $00

    ; R1: memory, increment, variable timing
    DMA_OUT %01010100           ; memory, inc, timing byte follows
    DMA_OUT %00000010           ; 2-cycle timing

    ; R2: I/O, fixed address, variable timing + prescaler
    DMA_OUT %01101000           ; I/O, fixed, timing byte follows
    DMA_OUT %00100010           ; 2-cycle + prescaler follows
    DMA_OUT PRESCALER           ; prescaler value

    ; R4: BURST mode, Port B address follows
    ;     Burst releases the bus during prescaler waits - CPU keeps running!
    DMA_OUT $CD                 ; burst mode (bit 7=1, bits 6:5=10)
    DMA_OUT SPECDRUM & $FF      ; Port B = $DF
    DMA_OUT SPECDRUM >> 8       ; Port B = $FF

    ; R5: stop on end of block
    DMA_OUT $82                 ; ($B2 for auto-restart/looping)

    ; Load + enable
    DMA_OUT $CF                 ; Load (initializes all counters)
    ; NOTE: $B3 (Force ready) is decoded but is a silent NOP in this RTL -
    ;       the READY/handshake system is not implemented. Left out here.
    ;       On a real Z8410 you would emit $B3 between $CF and $87 for
    ;       I/O destinations; on this core it is unnecessary.
    DMA_OUT $87                 ; Enable DMA - playback starts

    ret                         ; Return to BASIC, DMA plays in background

; =============================================================================
; zxnDDMA examples
;
; zxnDDMA is the zxnDMA (port $6B) with the DMA+ additional commands.
; Every core > 3.02.16 is equipped with it. The commands are listed in
;/docs/zxnDDMA/zxnddma.gde.
;
; This file is a whole program. Assemble it with:
;     sjasmplus zxnddma_examples.asm
; then run zxnddma_examples.nex on the Next. It shows four examples on
; Layer 2 (320x256), one after another, and then starts again. 320x256 covers
; the border too, so the white squares in the top left corner tell you which
; example is on screen:
;
;   1 square   clear the screen to dark grey with fill mode
;   2 squares  eight coloured bars and a box, with fill mode and an X,Y
;              destination
;   3 squares  40 balls over the bars, skipping the transparent byte
;   4 squares  dark blue, a green frame and an X of balls, drawn on the hidden
;              screen and then copied, all 80K at once, to the visible one
;
; Reset the Next to leave.
;
; Things to know about Layer 2 in 320x256:
;   - The screen is stored column by column: the byte after (x,y) is (x,y+1).
;     So a DMA "row" is a column on the screen. The row length is the height
;     and the number of rows is the width.
;   - 16K bank n is at physical address $40000 + n * $4000 (8K page n at
;     $40000 + n * $2000). Here the visible screen is banks 9-13 ($064000)
;     and the hidden screen banks 14-18 ($078000).
;
; Things to know about zxnDDMA:
;   - Every setting stays until $C3, so each example starts with $83,$C3.
;   - $DF sets all the mode flags at once.
;   - The X,Y form of $DF sets port B's address. Send it after WR4.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows
HIDDEN      equ %00100000       ; with XY: the hidden screen (NextReg $13)

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $12,9               ; visible screen: bank 9
    nextreg $13,14              ; hidden screen: bank 14
    nextreg $1C,1               ; open the Layer 2 clip window
    nextreg $18,0
    nextreg $18,159
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off
    nextreg $69,%10000000       ; Layer 2 on

main:
    ld a,$49                    ; dark grey
    call example1
    ld b,1                      ; one square
    call squares
    ld b,100                    ; 2 seconds
    call wait_frames

    call example2
    ld b,2
    call squares
    ld b,100
    call wait_frames

    call example3
    ld b,3
    call squares
    ld b,150
    call wait_frames

    call example4
    ld b,4
    call squares
    ld b,150
    call wait_frames

    jr main

; Draw B white squares in the top left corner of the visible screen, with the
; box routine from example 2
squares:
    xor a
    ld (target),a
    ld hl,4                     ; x of the first square
.next:
    ld (square+0),hl
    push hl
    push bc
    ld ix,square
    call box
    pop bc
    pop hl
    ld de,12
    add hl,de
    djnz .next
    ret

square:
    dw 0                        ; x
    db 4                        ; y
    dw 8,8                      ; width, height
    db $FF                      ; white

; -----------------------------------------------------------------------------
; Example 1: clear the screen with fill mode
;
; Fill mode writes the fill value and reads nothing, so it runs at twice the
; speed of a copy. The screen is 80K, more than one transfer of 64K, so it is
; done as 320 rows (columns) of 256 bytes. The address is given the long way
; here: physical $064000, bank 9.
;
; In: A = colour
; -----------------------------------------------------------------------------
example1:
    ld (clear_colour),a
    ld hl,clear_dma
    ld bc,(clear_dma_end-clear_dma)*256+DMA
    otir
    ret

clear_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B (fill mode never reads port A)
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
    dw $4000                    ;   bits 15:0 of $064000
    db $82                      ; WR5: stop at the end
    db $DB,$06                  ; port B bits 23:16 of $064000
    db $E3 : dw 256             ; row length: one column
    db $E7 : dw 320             ; rows: 320 columns
    db $EF : dw 256             ; port B stride: on to the next column
    db $F7                      ; fill value:
clear_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL
    db $CF,$87                  ; load, go
clear_dma_end:

; -----------------------------------------------------------------------------
; Example 2: boxes, with fill mode and an X,Y destination
;
; With the XY flag, $DF is followed by X (2 bytes) and Y (1 byte), and the
; DMA works out the address in the Layer 2 screen itself. It also sets port B's
; stride to 256, the next column. XY needs PHYSICAL as well.
; -----------------------------------------------------------------------------
example2:
    xor a                       ; draw on the visible screen
    ld (target),a
    ld ix,ex2_boxes
    ld b,(ex2_boxes_end-ex2_boxes)/8
    jp boxes

    macro BOX x,y,w,h,colour
        dw x
        db y
        dw w,h
        db colour
    endm

ex2_boxes:
    BOX   0,0,40,256,$E0        ; eight bars
    BOX  40,0,40,256,$F4
    BOX  80,0,40,256,$FC
    BOX 120,0,40,256,$1C
    BOX 160,0,40,256,$1F
    BOX 200,0,40,256,$03
    BOX 240,0,40,256,$A2
    BOX 280,0,40,256,$FF
    BOX  60,64,200,128,$00      ; a black box
    BOX  80,80,160,96,$6D       ; with a grey one inside
ex2_boxes_end:

; Draw B boxes from the list at IX
boxes:
    push bc
    call box
    ld de,8
    add ix,de
    pop bc
    djnz boxes
    ret

; Draw one box
; In: IX -> x (2 bytes), y (1), width (2), height (2), colour (1)
box:
    ld l,(ix+0)
    ld h,(ix+1)
    ld (box_x),hl
    ld a,(ix+2)
    ld (box_y),a
    ld l,(ix+3)                 ; rows = width
    ld h,(ix+4)
    ld (box_w),hl
    ld l,(ix+5)                 ; row length = height
    ld h,(ix+6)
    ld (box_h),hl
    ld a,(ix+7)
    ld (box_colour),a
    ld a,(target)
    or PHYSICAL|TWO_D|FILL|XY
    ld (box_flags),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ret

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length: the height
box_h:
    dw 0
    db $E7                      ; rows: the width
box_w:
    dw 0
    db $F7                      ; fill value: the colour
box_colour:
    db 0
    db $DF                      ; mode flags, then X and Y, after WR4
box_flags:
    db 0
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

target:
    db 0                        ; 0 = visible screen, HIDDEN = hidden screen

; -----------------------------------------------------------------------------
; Example 3: 40 balls, skipping the transparent byte
;
; The ball is 16x16 and lives at physical $090000 (8K page 40). Its background
; is $E3, and the TRANSPARENT flag leaves those bytes unwritten, so the bars
; from example 2 show round the balls.
;
; The full set-up is sent once. After that each ball needs only 7 bytes: the
; X,Y form of $DF, then $CF $87. Every other setting is still there.
; -----------------------------------------------------------------------------
example3:
    ld a,PHYSICAL|TWO_D|TRANSPARENT|XY
    ld (ball_flags),a
    call ball_setup
    ld e,30                     ; y
    ld d,4                      ; 4 rows of balls
.row:
    ld hl,12                    ; x
    ld b,10                     ; 10 balls in a row
.ball:
    push bc
    call ball_at
    ld bc,30
    add hl,bc
    pop bc
    djnz .ball
    ld a,e
    add a,56
    ld e,a
    dec d
    jr nz,.row
    ret

; The full set-up, without the destination and without the go
ball_setup:
    ld hl,ball_dma
    ld bc,(ball_dma_end-ball_dma)*256+DMA
    otir
    ret

ball_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw $0000                    ;   bits 15:0 of $090000
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $D7,$09                  ; port A bits 23:16 of $090000
    db $E3 : dw 16              ; row length: one column of the ball
    db $E7 : dw 16              ; rows: 16 columns
    db $EB : dw 16              ; port A stride: the ball's columns follow on
    db $F3,$E3                  ; transparent byte
ball_dma_end:

; Draw one ball: the short reload
; In: HL = x, E = y. Keeps HL, BC and DE.
ball_at:
    ld (ball_x),hl
    ld a,e
    ld (ball_y),a
    push hl
    push bc
    ld hl,ball_go
    ld bc,(ball_go_end-ball_go)*256+DMA
    otir
    pop bc
    pop hl
    ret

ball_go:
    db $DF                      ; mode flags, then X and Y
ball_flags:
    db 0
ball_x:
    dw 0
ball_y:
    db 0
    db $CF,$87                  ; load, go
ball_go_end:

; -----------------------------------------------------------------------------
; Example 4: draw on the hidden screen, then copy all 80K to the visible one
;
; The HIDDEN flag sends an X,Y destination to the screen in NextReg $13
; instead of $12. Nothing changes on screen while the picture is drawn.
; Then one transfer copies the whole hidden screen to the visible one. 80K is
; more than 64K, so the copy is 5 rows of 16K, with both strides 16K: one
; straight run. The address carries into bits 23:16 on its own.
; -----------------------------------------------------------------------------
example4:
    ld a,HIDDEN                 ; boxes go to the hidden screen
    ld (target),a
    ld ix,ex4_boxes
    ld b,(ex4_boxes_end-ex4_boxes)/8
    call boxes

    ld a,PHYSICAL|TWO_D|TRANSPARENT|XY|HIDDEN
    ld (ball_flags),a           ; and so do the balls
    call ball_setup
    ld hl,8                     ; a line of balls going down
    ld e,20
    ld b,40
.down:
    push bc
    call ball_at
    ld bc,7
    add hl,bc
    ld a,e
    add a,5
    ld e,a
    pop bc
    djnz .down
    ld hl,8                     ; and one going up
    ld e,215
    ld b,40
.up:
    push bc
    call ball_at
    ld bc,7
    add hl,bc
    ld a,e
    sub 5
    ld e,a
    pop bc
    djnz .up

    ld hl,copy_dma              ; now show it, all at once
    ld bc,(copy_dma_end-copy_dma)*256+DMA
    otir
    ret

ex4_boxes:
    BOX   0,0,320,256,$02       ; dark blue, the whole screen
    BOX  16,16,288,8,$1C        ; a green frame
    BOX  16,232,288,8,$1C
    BOX  16,24,8,208,$1C
    BOX 296,24,8,208,$1C
ex4_boxes_end:

copy_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw $8000                    ;   bits 15:0 of $078000 (hidden, bank 14)
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
    dw $4000                    ;   bits 15:0 of $064000 (visible, bank 9)
    db $82                      ; WR5: stop at the end
    db $D7,$07                  ; port A bits 23:16
    db $DB,$06                  ; port B bits 23:16
    db $E3 : dw 16384           ; row length: 16K
    db $E7 : dw 5               ; rows: 5, so 80K in all
    db $EB : dw 16384           ; port A stride
    db $EF : dw 16384           ; port B stride
    db $DF,PHYSICAL|TWO_D
    db $CF,$87                  ; load, go
copy_dma_end:

; -----------------------------------------------------------------------------
; Wait B frames (50 a second), by watching the video line in NextReg $1F
; -----------------------------------------------------------------------------
wait_frames:
    push bc
    ld bc,$243B                 ; select NextReg $1F
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.in:
    in a,(c)                    ; wait for line 192
    cp 192
    jr nz,.in
.out:
    in a,(c)                    ; and for it to end
    cp 192
    jr z,.out
    pop bc
    djnz wait_frames
    ret

; -----------------------------------------------------------------------------
; The ball, in 8K page 40: physical $40000 + 40 * $2000 = $090000.
; Layer 2 320x256 wants it column by column. This ball is the same either way
; round, so the lines below can be read as rows. A ball that isn't would have
; to be stored a column at a time.
; -----------------------------------------------------------------------------
    mmu 6,40,$C000
ball:

    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3

    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3

    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3

3.4  zxnddma_compare.asm
------------------------
Finding out whether the zxnDDMA is there, and the same job done by the CPU,
the zxnDMA and the zxnDDMA, timed.

; =============================================================================
; zxnDDMA check and compare
;
; Finds out whether the core has zxnDDMA, then draws the same job five ways and
; shows how long each took:
;
;   1  CPU, LDIR             opaque, one LDIR per column
;   2  CPU, skip $E3         transparent, a byte at a time
;   3  zxnDMA, per column    opaque, one transfer per column (16 per ball)
;   4  zxnDDMA, opaque          one transfer per ball
;   5  zxnDDMA, transparent     one transfer per ball, $E3 skipped
;
; The job is 32 balls of 16x16 on Layer 2 320x256. Each way draws into its
; own band, so you can see the results side by side: the opaque ways leave
; black corners round the balls ($E3 is see-through on Layer 2, and the
; fallback colour behind it is black); the transparent ways keep the stripes.
;
; On a core without zxnDDMA it says so, and does ways 1 to 3 only. Everything
; else - the background, the text - is drawn by the CPU, so it works on any
; core. Set FORCE_PLAIN to 1 to see that path on a zxnDDMA core.
;
; Measured on an issue 5 (3.02.21, 28MHz), the same every run:
;   1  CPU, LDIR            7.2 ms
;   2  CPU, skip $E3       15.6 ms
;   3  zxnDMA, per column   8.2 ms   (16 small transfers a ball: slower than
;                                     LDIR, because of the set-up bytes)
;   4  zxnDDMA, opaque         2.1 ms   3.4 times faster than LDIR
;   5  zxnDDMA, transparent    2.1 ms   7.4 times faster than the CPU doing it
;
; Assemble with:
;     sjasmplus zxnddma_compare.asm
; and run zxnddma_compare.nex. The results stay on screen; reset to leave.
;
; Finding zxnDDMA safely (see also zxnddma.gde, 2.5):
;   On a plain DMA the zxnDDMA command bytes are ignored, but the data bytes after
;   them are taken as register writes. So:
;   1. send the zxnDDMA bytes straight after $C3, before the ordinary set-up;
;   2. keep every zxnDDMA data byte below $80;
;   3. follow them with eight $83 (on zxnDDMA just "stop"; on a plain DMA they
;      finish any register write it was left in the middle of);
;   4. then copy one byte, choosing addresses whose low 16 bits are harmless.
;   Here the copy goes from a marker byte in this program to a scratch byte in
;   this program. A plain DMA writes the scratch byte. zxnDDMA, in physical mode,
;   writes $0B0000 + the scratch byte's address instead, in 8K page 60. The
;   program looks to see which one changed.
;
; Timing: each job starts on video line 0 and the line it ends on is read
; from NextRegs $1E and $1F. A line is 64 microseconds. A job must take less
; than one frame (20ms) for this to work.
;
; Things to know:
;   - This program is in 16K bank 2 (CPU $8000-$BFFF), which is physical
;     $048000-$04BFFF. So for anything in it, the physical address is $04
;     then the CPU address: the ball is at $04 : ball.
;   - The CPU and the plain zxnDMA reach Layer 2 through MMU slots 6 and 7
;     ($C000-$FFFF). In 320x256, x,y is byte x * 256 + y of the screen: 8K
;     page 18 + x / 32 (bank 9 is pages 18-27), at (x mod 32) * 256 + y.
;   - The zxnDMA and zxnDDMA use the default 3-cycle timing here, so they are
;     compared like with like. 2-cycle timing makes both about 12% faster.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

FORCE_PLAIN equ 0               ; 1 = act as if there were no zxnDDMA

DMA         equ $6B
SCREEN      equ 9               ; Layer 2: 16K bank 9, 8K pages 18-27
SCREEN_PAGE equ SCREEN*2
PROBE_PAGE  equ 60              ; where zxnDDMA writes the probe byte

; $DF mode flags
PHYSICAL    equ %00000001
TWO_D       equ %00000010
TRANSPARENT equ %00000100
XY          equ %00010000

; colours
BLUE        equ $01
WHITE       equ $FF
YELLOW      equ $FC
GREEN       equ $1C
RED         equ $E0

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0
    nextreg $CE,0
    nextreg $54,4               ; this program: bank 2 in slots 4 and 5
    nextreg $55,5
    ld bc,$123B                 ; no Layer 2 paging over $0000-$3FFF
    xor a
    out (c),a
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $12,SCREEN
    nextreg $1C,1               ; open the Layer 2 clip window
    nextreg $18,0
    nextreg $18,159
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off
    nextreg $69,%10000000       ; Layer 2 on

    call draw_background
    call detect

    ld a,(have_zxnddma)         ; the title
    or a
    ld ix,title_yes
    ld a,GREEN
    jr nz,.title
    ld ix,title_no
    ld a,RED
.title:
    ld (ink),a
    ld hl,8
    ld e,4
    call print
    ld a,WHITE
    ld (ink),a
    ld ix,title_2
    ld hl,8
    ld e,16
    call print
    ld ix,title_time
    ld hl,184
    ld e,16
    call print
    ld ix,title_vs
    ld hl,264
    ld e,16
    call print

    call run_all
    jr $                        ; done: the results stay on screen

title_yes:
    db "ZXNDDMA FOUND",0
title_no:
    db "NO ZXNDDMA ON THIS CORE",0
title_2:
    db "32 BALLS OF 16X16",0
title_time:
    db "TIME",0
title_vs:
    db "VS 1",0

; -----------------------------------------------------------------------------
; Find out whether the DMA has zxnDDMA. Sets have_zxnddma to 1 if it has.
; -----------------------------------------------------------------------------
detect:
    xor a
    ld (have_zxnddma),a
    ld (probe_to),a             ; clear the two places the byte can land
    nextreg $57,PROBE_PAGE
    ld ($E000+(probe_to&$1FFF)),a

    ld hl,detect_dma
    ld bc,(detect_dma_end-detect_dma)*256+DMA
    otir

    ld a,($E000+(probe_to&$1FFF))
    cp $5A
    ret nz                      ; not there: no zxnDDMA
    if FORCE_PLAIN = 0
    ld a,1
    ld (have_zxnddma),a
    endif
    ret

detect_dma:
    db $83,$C3                  ; stop, reset
    db $D7,$04                  ; zxnDDMA: port A bits 23:16 (this program)
    db $DB,$0B                  ; zxnDDMA: port B bits 23:16: $0B8000 + ...
    db $DF,PHYSICAL             ; zxnDDMA: physical addresses
    db $83,$83,$83,$83          ; finish anything a plain DMA was left
    db $83,$83,$83,$83          ; in the middle of
    db $7D                      ; WR0: A to B, port A address, length
    dw probe_from,1             ;   one byte
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
    dw probe_to
    db $82                      ; WR5: stop at the end
    db $CF,$87                  ; load, go
detect_dma_end:

probe_from:
    db $5A                      ; the marker
probe_to:
    db 0                        ; scratch: a plain DMA writes the marker here
    assert probe_to >= $8000 && probe_to < $A000  ; so zxnDDMA writes page 60

have_zxnddma:
    db 0

; -----------------------------------------------------------------------------
; Run the five ways, one band each
; -----------------------------------------------------------------------------
    macro WAY wsetup, wdraw, wname, wneeds
        dw wsetup, wdraw, wname
        db wneeds
    endm

ways:
    WAY 0,           cpu_ldir_ball, name_1, 0
    WAY 0,           cpu_skip_ball, name_2, 0
    WAY dma_setup,   dma_ball,      name_3, 0
    WAY plus_opaque, plus_ball,     name_4, 1
    WAY plus_transp, plus_ball,     name_5, 1
ways_end:

name_1: db "1 CPU, LDIR",0
name_2: db "2 CPU, SKIP $E3",0
name_3: db "3 ZXNDMA, PER COLUMN",0
name_4: db "4 ZXNDDMA, OPAQUE",0
name_5: db "5 ZXNDDMA, TRANSPARENT",0
not_here:
    db "NOT ON THIS CORE",0

run_all:
    ld iy,ways
    ld hl,times
    ld (time_at),hl
    ld a,32                     ; first band at y = 32
    ld (band_y),a
.way:
    ld a,WHITE                  ; the name
    ld (ink),a
    ld l,(iy+4)
    ld h,(iy+5)
    push hl
    pop ix
    ld hl,8
    ld a,(band_y)
    ld e,a
    call print

    ld a,(iy+6)                 ; needs zxnDDMA?
    or a
    jr z,.run
    ld a,(have_zxnddma)
    or a
    jr nz,.run
    ld a,RED
    ld (ink),a
    ld ix,not_here
    ld hl,184
    ld a,(band_y)
    ld e,a
    call print
    ld hl,0                     ; no time
    jr .store

.run:
    call run_way                ; HL = lines taken
.store:
    ex de,hl
    ld hl,(time_at)
    ld (hl),e
    inc hl
    ld (hl),d
    inc hl
    ld (time_at),hl
    ld a,d
    or e
    call nz,show_time           ; DE = lines

    ld a,(band_y)
    add a,44
    ld (band_y),a
    ld de,7                     ; next way
    add iy,de
    push iy
    pop hl
    ld de,ways_end
    or a
    sbc hl,de
    jr nz,.way
    ret

band_y:
    db 0
time_at:
    dw 0
times:
    ds 10                       ; lines each way took (0 = not run)

; Draw this way's 32 balls, timed. Out: HL = lines taken
run_way:
    ld l,(iy+2)                 ; the ball routine
    ld h,(iy+3)
    ld (.call+1),hl
    call wait_line_0
    ld l,(iy+0)                 ; its set-up, if any
    ld h,(iy+1)
    ld a,h
    or l
    call nz,jump_hl
    ld a,(band_y)               ; two rows of 16 balls
    add a,10
    ld e,a
    ld b,2
.row:
    push bc
    ld hl,8
    ld b,16
.ball:
    push bc
    push hl
    push de
.call:
    call 0
    pop de
    pop hl
    pop bc
    push de
    ld de,19
    add hl,de
    pop de
    djnz .ball
    pop bc
    ld a,e
    add a,16
    ld e,a
    djnz .row
    jp read_line

jump_hl:
    jp (hl)

; Wait for video line 0
wait_line_0:
    call read_line
    ld a,h
    or l
    jr nz,wait_line_0
    ret

; HL = the video line now. The high bit (NextReg $1E) and the low byte ($1F)
; are read separately, so the line can move on in between: 255 then 256 would
; read as 0. So read the high bit again after the low byte, and try again if
; it changed.
read_line:
    call .high
    ld h,a
    ld a,$1F                    ; low byte
    out (c),a
    inc b
    in l,(c)
    call .high
    cp h
    jr nz,read_line
    ret
.high:
    ld bc,$243B
    ld a,$1E
    out (c),a
    inc b
    in a,(c)
    and 1
    dec b
    ret

; Print the time (DE lines) as ms, and how many times faster than way 1
show_time:
    push de
    ld h,d                      ; tenths of a ms = (lines * 64 + 50) / 100
    ld l,e
    add hl,hl
    add hl,hl
    add hl,hl
    add hl,hl
    add hl,hl
    add hl,hl
    ld de,50
    add hl,de
    ld de,100
    call divide
    ld de,text
    call put_tenths
    ld hl,ms
    call put_string
    ld a,YELLOW
    ld (ink),a
    ld ix,text
    ld hl,184
    ld a,(band_y)
    ld e,a
    call print

    pop de                      ; times faster = way 1 / this way
    ld hl,(times)               ; (in tenths: way 1 * 10 + this / 2) / this
    ld b,h
    ld c,l
    add hl,hl
    add hl,hl
    add hl,bc
    add hl,hl
    ld b,d
    ld c,e
    srl b
    rr c
    add hl,bc
    call divide
    ld de,text
    call put_tenths
    ld a,"X"
    ld (de),a
    inc de
    xor a
    ld (de),a
    ld ix,text
    ld hl,264
    ld a,(band_y)
    ld e,a
    jp print

ms:
    db " MS",0
text:
    ds 12

; HL = HL / DE, DE = the remainder (unsigned)
divide:
    ld b,h
    ld c,l
    ld hl,0
    ld a,16
.bit:
    sla c
    rl b
    adc hl,hl
    sbc hl,de
    jr nc,.fits
    add hl,de
    dec a
    jr nz,.bit
    jr .done
.fits:
    inc c
    dec a
    jr nz,.bit
.done:
    ex de,hl                    ; DE = the remainder
    ld h,b
    ld l,c
    ret

; Write HL tenths as "N.N" at DE. DE ends on the 0 after it.
put_tenths:
    push de
    ld de,10
    call divide                 ; HL = the whole part, E = the tenths
    ld a,e
    ld (tenths),a
    pop de
    call put_number
    ld a,"."
    ld (de),a
    inc de
    ld a,(tenths)
    add a,"0"
    ld (de),a
    inc de
    xor a
    ld (de),a
    ret

tenths:
    db 0

; Write HL in decimal at DE, no leading zeros (DE moves on)
put_number:
    push de
    ld de,10
    call divide                 ; HL = the rest, E = the last digit
    ld a,e
    pop de
    push af
    ld a,h
    or l
    call nz,put_number          ; the digits in front of it first
    pop af
    add a,"0"
    ld (de),a
    inc de
    ret

; Copy the zero-ended string at HL to DE (DE moves on, stops on the 0)
put_string:
    ld a,(hl)
    ld (de),a
    or a
    ret z
    inc hl
    inc de
    jr put_string

; -----------------------------------------------------------------------------
; The five ways to draw a ball. Each takes HL = x, E = y.
; -----------------------------------------------------------------------------

; 1. CPU, opaque: one LDIR per column
cpu_ldir_ball:
    call map_xy                 ; HL = the ball's top left on screen
    ex de,hl
    ld hl,ball
    ld a,16
.col:
    push de
    ld bc,16
    ldir
    pop de
    inc d                       ; next column: 256 bytes on
    dec a
    jr nz,.col
    ret

; 2. CPU, transparent: a byte at a time, skipping $E3
cpu_skip_ball:
    call map_xy
    ex de,hl
    ld hl,ball
    ld c,16
.col:
    push de
    ld b,16
.byte:
    ld a,(hl)
    cp $E3
    jr z,.skip
    ld (de),a
.skip:
    inc hl
    inc e
    djnz .byte
    pop de
    inc d
    dec c
    jr nz,.col
    ret

; 3. zxnDMA, opaque: the plain DMA has no stride, so one transfer per column
dma_setup:
    ld hl,dma_setup_bytes
    ld bc,(dma_setup_end-dma_setup_bytes)*256+DMA
    otir
    ret

dma_setup_bytes:
    db $83,$C3                  ; stop, reset
    db $14,$10                  ; WR1, WR2: memory, increment
    db $82                      ; WR5: stop at the end
dma_setup_end:

dma_ball:
    call map_xy
    ld (col_to),hl
    ld hl,ball
    ld (col_from),hl
    ld a,16
.col:
    push af
    ld hl,col_dma
    ld bc,(col_dma_end-col_dma)*256+DMA
    otir
    ld hl,(col_from)            ; next column of the ball: 16 bytes on
    ld de,16
    add hl,de
    ld (col_from),hl
    ld hl,col_to+1              ; next column of the screen: 256 bytes on
    inc (hl)
    pop af
    dec a
    jr nz,.col
    ret

col_dma:
    db $7D                      ; WR0: A to B, port A address, length
col_from:
    dw 0
    dw 16                       ;   one column
    db $AD                      ; WR4: continuous, port B address follows
col_to:
    dw 0
    db $CF,$87                  ; load, go
col_dma_end:

; 4 and 5. zxnDDMA: one transfer per ball. The set-up is sent once.
plus_opaque:
    ld a,PHYSICAL|TWO_D|XY
    jr plus_setup
plus_transp:
    ld a,PHYSICAL|TWO_D|TRANSPARENT|XY
plus_setup:
    ld (plus_flags),a
    ld hl,plus_setup_bytes
    ld bc,(plus_setup_end-plus_setup_bytes)*256+DMA
    otir
    ret

plus_setup_bytes:
    db $83,$C3                  ; stop, reset
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $1D                      ; WR0: A to B, port A address: the ball
    dw ball
    db $D7,$04                  ; port A bits 23:16: this program's bank
    db $E3 : dw 16              ; row length: a column of 16 pixels
    db $E7 : dw 16              ; rows: 16 columns
    db $EB : dw 16              ; port A stride: the ball's columns follow on
    db $F3,$E3                  ; transparent byte (used by way 5)
plus_setup_end:

plus_ball:
    ld (plus_x),hl
    ld a,e
    ld (plus_y),a
    ld hl,plus_one
    ld bc,(plus_one_end-plus_one)*256+DMA
    otir
    ret

plus_one:
    db $DF
plus_flags:
    db 0
plus_x:
    dw 0
plus_y:
    db 0
    db $CF,$87                  ; load, go
plus_one_end:

; -----------------------------------------------------------------------------
; Page the screen at x into MMU slots 6 and 7, and point at x,y.
; In: HL = x, E = y. Out: HL = the CPU address of x,y (in $C000-$FFFF).
; Two pages are paged in, so anything up to 32 columns wide fits.
; -----------------------------------------------------------------------------
map_xy:
    ld a,l                      ; high byte: $C0 + (x mod 32)
    and 31
    add a,$C0
    ld d,a
    ld a,l                      ; page: 18 + x / 32
    and $E0
    or h
    rlca
    rlca
    rlca
    add a,SCREEN_PAGE
    nextreg $56,a
    inc a
    nextreg $57,a
    ex de,hl                    ; HL = address, E was y
    ret

; -----------------------------------------------------------------------------
; Text, drawn by the CPU with a 1-bit 8x8 font (works on any core)
; In: IX -> zero-ended text, HL = x, E = y. Colour in ink.
; -----------------------------------------------------------------------------
print:
    ld a,(ix+0)
    or a
    ret z
    push hl
    push de
    call print_char
    pop de
    pop hl
    ld bc,8
    add hl,bc
    inc ix
    jr print

print_char:
    ld (char),a
    call map_xy                 ; HL = screen
    ld a,(char)
    sub 32
    push hl
    ld l,a                      ; DE = the letter's 8 bytes
    ld h,0
    add hl,hl
    add hl,hl
    add hl,hl
    ld de,font
    add hl,de
    ex de,hl
    pop hl
    ld c,$80                    ; C = this column's bit
.col:
    push hl
    push de
    ld b,8
.row:
    ld a,(de)
    and c
    jr z,.blank
    ld a,(ink)
    ld (hl),a
.blank:
    inc de
    inc l
    djnz .row
    pop de
    pop hl
    inc h                       ; next column
    srl c
    jr nc,.col                  ; after 8 columns the bit drops out
    ret

ink:
    db WHITE
char:
    db 0

; -----------------------------------------------------------------------------
; The background, drawn by the CPU: dark blue, with stripes behind each band's
; two rows of balls. Every column is the same, so one column is built and
; copied to all 320.
; -----------------------------------------------------------------------------
draw_background:
    ld hl,column                ; dark blue all the way down
    ld de,column+1
    ld bc,255
    ld (hl),BLUE
    ldir
    ld hl,column+32+10          ; the stripes: 5 bands, 44 lines apart

.band:

.line:

    ld a,$92
    jr z,.colour
    ld a,$49
.colour:

    inc hl
    djnz .line
    pop hl
    ld de,44
    add hl,de
    dec c
    jr nz,.band

    ld a,SCREEN_PAGE            ; copy the column to all 320
    ld b,10                     ; 10 pages of 32 columns
.page:
    push bc
    nextreg $56,a
    push af
    ld de,$C000
    ld b,32
.copy:
    push bc
    ld hl,column
    ld bc,256
    ldir
    pop bc
    djnz .copy
    pop af
    inc a
    pop bc
    djnz .page
    ret

column:
    ds 256

3.5  zxnddma_sprites.asm

120 software sprites, double buffered, at 50 frames a second.

; =============================================================================
; zxnDDMA software sprites, double buffered
;
; NUM balls bounce round a Layer 2 320x256 screen. The zxnDDMA does all the
; drawing: the CPU only moves the balls and tells the DMA where to put them.
;
; Assemble with:
;     sjasmplus zxnddma_sprites.asm
; and run zxnddma_sprites.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; How it works:
;   - There are two screens, A (bank 9) and B (bank 14). One is shown
;     (NextReg $12) while the other is drawn (NextReg $13). When the picture
;     has been sent to the display (line 224), they swap.
;   - A clean copy of the background lives in bank 20. It is never shown.
;   - Each frame, on the screen being drawn:
;       1. Rub out each ball by copying back the 16x16 square of background
;          where it was. That is where it was two frames ago, the last time
;          this screen was drawn.
;       2. Move the balls.
;       3. Draw each ball, skipping its transparent byte ($E3).
;   - Both 1 and 3 use the X,Y form of $DF with the HIDDEN flag, so the DMA
;     works out the address in the screen in NextReg $13 itself.
;
; Things to know:
;   - Layer 2 320x256 is stored column by column, so a DMA "row" is a column
;     of 16 pixels here, and there are 16 of them.
;   - 16K bank n is at physical address $40000 + n * $4000, and 8K page n at
;     $40000 + n * $2000.
;   - Every setting stays until $C3. So after one set-up a frame, each ball
;     needs only a few bytes: its source, its X,Y, then $CF $87.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B
NUM         equ 120             ; number of balls (up to 255)
                                ; Each ball takes about 0.13ms (2 video
                                ; lines) to rub out and draw, so 120 balls
                                ; use 244 of the 312 lines in a 50Hz frame
                                ; (and fit in 60Hz too). Much more than 140
                                ; and it drops to 25 frames a second.
                                ; Measured on an issue 5 at 28MHz.

SCREEN_A    equ 9               ; 16K banks
SCREEN_B    equ 14
BACKGROUND  equ 20
BALL_PAGE   equ 60              ; 8K page

SCREEN_A_AT equ $40000+SCREEN_A*$4000      ; $064000
SCREEN_B_AT equ $40000+SCREEN_B*$4000      ; $078000
BACK_AT     equ $40000+BACKGROUND*$4000    ; $090000
BALL_AT     equ $40000+BALL_PAGE*$2000     ; $0B8000

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows
HIDDEN      equ %00100000       ; with XY: the screen in NextReg $13

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $69,0               ; Layer 2 off while we set up
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $1C,1               ; open the Layer 2 clip window
    nextreg $18,0
    nextreg $18,159
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off

    nextreg $12,BACKGROUND      ; draw the background in bank 20 with X,Y
    call draw_background
    ld a,SCREEN_A_AT>>16        ; then copy it to both screens
    ld hl,SCREEN_A_AT&$FFFF
    call copy_background
    ld a,SCREEN_B_AT>>16
    ld hl,SCREEN_B_AT&$FFFF
    call copy_background

    nextreg $12,SCREEN_A        ; shown
    nextreg $13,SCREEN_B        ; drawn
    call init_balls
    nextreg $69,%10000000       ; Layer 2 on

frame:
    call wait_bottom
    call swap_screens
    call rub_out
    call move
    call draw
    jr frame

; -----------------------------------------------------------------------------
; Wait for line 224, just below the bottom of the 320x256 picture
; -----------------------------------------------------------------------------
wait_bottom:
    ld bc,$243B                 ; select NextReg $1F, the video line
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.out:
    in a,(c)                    ; if we are on line 224 already, let it end
    cp 224
    jr z,.out
.in:
    in a,(c)
    cp 224
    jr nz,.in
    ret

; -----------------------------------------------------------------------------
; Show the screen we have just drawn, and draw on the other one
; -----------------------------------------------------------------------------
swap_screens:
    ld a,(shown)
    ld b,a
    ld a,(drawn)
    ld (shown),a
    nextreg $12,a
    ld a,b
    ld (drawn),a
    nextreg $13,a
    ld hl,(where_shown)         ; and swap their lists of ball positions
    ld de,(where_drawn)
    ld (where_shown),de
    ld (where_drawn),hl
    ret

shown:
    db SCREEN_A
drawn:
    db SCREEN_B
where_shown:
    dw where_a                  ; where the balls are on each screen
where_drawn:
    dw where_b

; -----------------------------------------------------------------------------
; 1. Rub out: copy 16x16 of background back over each ball
;
; The background is laid out like a screen, so the square at (x,y) starts at
; BACK_AT + x * 256 + y.
; -----------------------------------------------------------------------------
rub_out:
    ld hl,rub_setup
    ld bc,(rub_setup_end-rub_setup)*256+DMA
    otir
    ld ix,(where_drawn)
    ld b,NUM
.next:
    push bc
    ld l,(ix+0)                 ; x
    ld h,(ix+1)
    ld (rub_x),hl
    ld a,(ix+2)                 ; y
    ld (rub_y),a
    ld (rub_from),a             ; source bits 7:0 = y
    ld a,l
    ld (rub_from+1),a           ; bits 15:8 = x bits 7:0
    ld a,h
    add a,BACK_AT>>16
    ld (rub_from_hi),a          ; bits 23:16 = $09 + x bit 8
    ld hl,rub_one
    ld bc,(rub_one_end-rub_one)*256+DMA
    otir
    ld de,3
    add ix,de
    pop bc
    djnz .next
    ret

rub_setup:
    db $83,$C3                  ; stop, reset
    db $54,$02                  ; WR1: memory, increment, 2-cycle timing
    db $50,$02                  ; WR2: memory, increment, 2-cycle timing
                                ; (12% faster than the default 3 cycles;
                                ; checked on issue 5. If a board shows wrong
                                ; pixels, use $14,$10 for the default.)
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3 : dw 16              ; row length: a column of 16 pixels
    db $E7 : dw 16              ; rows: 16 columns
    db $EB : dw 256             ; port A stride: the background's next column
rub_setup_end:

rub_one:
    db $1D                      ; WR0: A to B, port A address
rub_from:
    dw 0
    db $D7                      ; port A bits 23:16
rub_from_hi:
    db 0
    db $DF,PHYSICAL|TWO_D|XY|HIDDEN
rub_x:
    dw 0
rub_y:
    db 0
    db $CF,$87                  ; load, go
rub_one_end:

; -----------------------------------------------------------------------------
; 2. Move the balls, bouncing off the edges, and note where they are now
; -----------------------------------------------------------------------------
move:
    ld ix,balls
    ld iy,(where_drawn)
    ld b,NUM
.next:
    ld l,(ix+0)                 ; x = x + dx
    ld h,(ix+1)
    ld a,(ix+3)
    ld e,a
    rla
    sbc a,a
    ld d,a
    add hl,de
    ld a,h                      ; 0 to 303 is fine
    cp 1
    jr c,.x_ok
    ld a,l
    cp 304-256
    jr c,.x_ok
    ld a,(ix+3)                 ; off the edge: turn round, stay put
    neg
    ld (ix+3),a
    ld l,(ix+0)
    ld h,(ix+1)
.x_ok:
    ld (ix+0),l
    ld (ix+1),h
    ld (iy+0),l
    ld (iy+1),h

    ld a,(ix+2)                 ; y = y + dy
    add a,(ix+4)
    cp 241                      ; 0 to 240 is fine
    jr c,.y_ok
    ld a,(ix+4)                 ; off the edge: turn round, stay put
    neg
    ld (ix+4),a
    ld a,(ix+2)
.y_ok:
    ld (ix+2),a
    ld (iy+2),a

    ld de,5
    add ix,de
    ld de,3
    add iy,de
    djnz .next
    ret

; -----------------------------------------------------------------------------
; 3. Draw the balls, skipping the transparent byte
; -----------------------------------------------------------------------------
draw:
    ld hl,draw_setup            ; the rub-out set-up is still there,
    ld bc,(draw_setup_end-draw_setup)*256+DMA
    otir                        ; so only these settings change
    ld ix,(where_drawn)
    ld b,NUM
.next:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (draw_x),hl
    ld a,(ix+2)
    ld (draw_y),a
    ld hl,draw_one
    ld bc,(draw_one_end-draw_one)*256+DMA
    otir
    ld de,3
    add ix,de
    pop bc
    djnz .next
    ret

draw_setup:
    db $EB : dw 16              ; port A stride: the ball's columns follow on
    db $F3,$E3                  ; transparent byte
    db $1D                      ; WR0: A to B, port A address: the ball
    dw BALL_AT&$FFFF
    db $D7,BALL_AT>>16          ; port A bits 23:16
draw_setup_end:

draw_one:                       ; 7 bytes a ball
    db $DF,PHYSICAL|TWO_D|TRANSPARENT|XY|HIDDEN
draw_x:
    dw 0
draw_y:
    db 0
    db $CF,$87                  ; load, go
draw_one_end:

; -----------------------------------------------------------------------------
; Start the balls in random places, going in random directions
; -----------------------------------------------------------------------------
init_balls:
    ld ix,balls
    ld iy,where_a
    ld b,NUM
.next:
    push bc
    call random                 ; x: 0 to 511, folded into 0 to 303
    ld a,h
    and 1
    ld h,a
    jr z,.x_ok
    ld a,l
    cp 304-256
    jr c,.x_ok
    ld h,0
.x_ok:
    ld (ix+0),l
    ld (ix+1),h
    ld (iy+0),l                 ; screen A has nothing to rub out yet,
    ld (iy+1),h                 ; so any position will do

    call random                 ; y: 0 to 255, folded into 0 to 240
    ld a,l
    cp 241
    jr c,.y_ok
    sub 16
.y_ok:
    ld (ix+2),a
    ld (iy+2),a

    ld a,h                      ; dx: 1 to 4, either way
    and 3
    inc a
    bit 7,h
    jr z,.dx
    neg
.dx:
    ld (ix+3),a
    ld a,h                      ; dy: 1 to 2, either way
    rrca
    rrca
    and 1
    inc a
    bit 6,h
    jr z,.dy
    neg
.dy:
    ld (ix+4),a

    ld de,5
    add ix,de
    ld de,3
    add iy,de
    pop bc
    djnz .next
    ld hl,where_a               ; the same for screen B
    ld de,where_b
    ld bc,NUM*3
    ldir
    ret

; HL = a new random number (16-bit xorshift)
random:
    ld hl,(seed)
    ld a,h
    rra
    ld a,l
    rra
    xor h
    ld h,a
    ld a,l
    rra
    ld a,h
    rra
    xor l
    ld l,a
    xor h
    ld h,a
    ld (seed),hl
    ret

seed:
    dw 1

; -----------------------------------------------------------------------------
; The background: eight bars with black lines across, drawn with fill mode
; into the screen in NextReg $12 (here the background bank)
; -----------------------------------------------------------------------------
draw_background:
    ld ix,background
    ld b,(background_end-background)/8
.next:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (box_x),hl
    ld a,(ix+2)
    ld (box_y),a
    ld l,(ix+3)                 ; rows = width
    ld h,(ix+4)
    ld (box_w),hl
    ld l,(ix+5)                 ; row length = height
    ld h,(ix+6)
    ld (box_h),hl
    ld a,(ix+7)
    ld (box_colour),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ld de,8
    add ix,de
    pop bc
    djnz .next
    ret

    macro BOX x,y,w,h,colour
        dw x
        db y
        dw w,h
        db colour
    endm

background:
    BOX   0,0,40,256,$E0        ; eight bars
    BOX  40,0,40,256,$F4
    BOX  80,0,40,256,$FC
    BOX 120,0,40,256,$1C
    BOX 160,0,40,256,$1F
    BOX 200,0,40,256,$03
    BOX 240,0,40,256,$A2
    BOX 280,0,40,256,$6D
    BOX 0, 12,320,8,$00         ; black lines across
    BOX 0, 44,320,8,$00
    BOX 0, 76,320,8,$00
    BOX 0,108,320,8,$00
    BOX 0,140,320,8,$00
    BOX 0,172,320,8,$00
    BOX 0,204,320,8,$00
    BOX 0,236,320,8,$00
background_end:

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length: the height
box_h:
    dw 0
    db $E7                      ; rows: the width
box_w:
    dw 0
    db $F7                      ; fill value: the colour
box_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL|XY
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

; Copy the whole background (80K) to a screen
; In: A = screen address bits 23:16, HL = bits 15:0
copy_background:
    ld (copy_to_hi),a
    ld (copy_to),hl
    ld hl,copy_dma
    ld bc,(copy_dma_end-copy_dma)*256+DMA
    otir
    ret

copy_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw BACK_AT&$FFFF
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
copy_to:
    dw 0
    db $82                      ; WR5: stop at the end
    db $D7,BACK_AT>>16          ; port A bits 23:16
    db $DB                      ; port B bits 23:16
copy_to_hi:
    db 0
    db $E3 : dw 16384           ; 5 rows of 16K: 80K in one go
    db $E7 : dw 5
    db $EB : dw 16384
    db $EF : dw 16384
    db $DF,PHYSICAL|TWO_D
    db $CF,$87                  ; load, go
copy_dma_end:

; -----------------------------------------------------------------------------
; The balls: x (2 bytes), y, dx, dy
; and where each one is on screen A and on screen B: x (2 bytes), y
; -----------------------------------------------------------------------------
balls:
    ds NUM*5
where_a:
    ds NUM*3
where_b:
    ds NUM*3

; -----------------------------------------------------------------------------
; The ball, in 8K page 60. Layer 2 320x256 wants it column by column. This
; ball is the same either way round, so the lines below can be read as rows.
; -----------------------------------------------------------------------------
    mmu 6,BALL_PAGE,$C000
ball:
    db $E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3,$E3
    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3
    db $E3,$E0,$E0,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3
    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3
    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3
    db $E3,$E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3

    savenex open "zxnddma_sprites.nex",start,$BFFE
    savenex core 3,2,21
    savenex auto

3.6  zxnddma_clip.asm
---------------------
Sprites clipped at all four screen edges.

; =============================================================================
; zxnDDMA clipped sprites
;
; 40 balls drift across a Layer 2 320x256 screen and wrap round all four
; edges. Where a ball is partly off the screen, only the part on the screen is
; drawn. This is the clipping every game needs. Drawing is double buffered,
; as in zxnddma_sprites.asm.
;
; Assemble with:
;     sjasmplus zxnddma_clip.asm
; and run zxnddma_clip.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; Why clip? Layer 2 320x256 is stored column by column, 256 bytes a column,
; and the zxnDDMA X,Y form does no checking. So a ball drawn whole:
;   - past the bottom edge, carries on into the top of the next column, so
;     its bottom half shows at the top of the screen, one pixel to the right;
;   - past the right edge, carries on past the end of the screen, into
;     whatever memory follows it (here, the other screen);
;   - past the left or top edge, needs a negative X or Y, which the X,Y form
;     can't take.
;
; How to clip a 16x16 picture at (x,y), with x and y signed:
;   - Columns: skip the first c0 = -x columns when x < 0. Stop at x = 319.
;   - Rows: skip the first r0 = -y rows when y < 0. Stop at y = 255.
;   - Start the source c0 * 16 + r0 bytes in (16 bytes a column).
;   - Draw at (x + c0, y + r0), with row length = the rows left and number
;     of rows = the columns left. The source stride stays 16.
; The rub-out is clipped the same way, so it only copies back what was drawn.
;
; Things to know:
;   - 16K bank n is at physical address $40000 + n * $4000, and 8K page n at
;     $40000 + n * $2000.
;   - Every setting stays until $C3. Here each ball sends its own row length
;     and number of rows, because clipping changes them.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B
NUM         equ 40              ; number of balls (up to 255)
SIZE        equ 16              ; each ball is 16x16

SCREEN_A    equ 9               ; 16K banks
SCREEN_B    equ 14
BACKGROUND  equ 20
BALL_PAGE   equ 60              ; 8K page

SCREEN_A_AT equ $40000+SCREEN_A*$4000      ; $064000
SCREEN_B_AT equ $40000+SCREEN_B*$4000      ; $078000
BACK_AT     equ $40000+BACKGROUND*$4000    ; $090000
BALL_AT     equ $40000+BALL_PAGE*$2000     ; $0B8000

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows
HIDDEN      equ %00100000       ; with XY: the screen in NextReg $13

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $69,0               ; Layer 2 off while we set up
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $1C,1               ; open the Layer 2 clip window
    nextreg $18,0
    nextreg $18,159
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off

    nextreg $12,BACKGROUND      ; draw the background in bank 20 with X,Y
    call draw_background
    ld a,SCREEN_A_AT>>16        ; then copy it to both screens
    ld hl,SCREEN_A_AT&$FFFF
    call copy_background
    ld a,SCREEN_B_AT>>16
    ld hl,SCREEN_B_AT&$FFFF
    call copy_background

    nextreg $12,SCREEN_A        ; shown
    nextreg $13,SCREEN_B        ; drawn
    call init_balls
    nextreg $69,%10000000       ; Layer 2 on

frame:
    call wait_bottom
    call swap_screens
    call rub_out
    call move
    call draw
    jr frame

; -----------------------------------------------------------------------------
; Wait for line 224, just below the bottom of the 320x256 picture
; -----------------------------------------------------------------------------
wait_bottom:
    ld bc,$243B                 ; select NextReg $1F, the video line
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.out:
    in a,(c)                    ; if we are on line 224 already, let it end
    cp 224
    jr z,.out
.in:
    in a,(c)
    cp 224
    jr nz,.in
    ret

; -----------------------------------------------------------------------------
; Show the screen we have just drawn, and draw on the other one
; -----------------------------------------------------------------------------
swap_screens:
    ld a,(shown)
    ld b,a
    ld a,(drawn)
    ld (shown),a
    nextreg $12,a
    ld a,b
    ld (drawn),a
    nextreg $13,a
    ld hl,(where_shown)         ; and swap their lists of what is drawn
    ld de,(where_drawn)
    ld (where_shown),de
    ld (where_drawn),hl
    ret

shown:
    db SCREEN_A
drawn:
    db SCREEN_B
where_shown:
    dw where_a
where_drawn:
    dw where_b

; -----------------------------------------------------------------------------
; 1. Rub out: copy back the background under the part of each ball that was
; drawn. The background is laid out like a screen, so (x,y) in it is at
; BACK_AT + x * 256 + y.
;
; Each note: x (2 bytes), y, columns, rows, source offset. Columns = 0 means
; nothing was drawn.
; -----------------------------------------------------------------------------
rub_out:
    ld hl,rub_setup
    ld bc,(rub_setup_end-rub_setup)*256+DMA
    otir
    ld ix,(where_drawn)
    ld b,NUM
.next:
    ld a,(ix+3)                 ; nothing drawn?
    or a
    jr z,.skip
    push bc
    ld (rub_cols),a
    ld a,(ix+4)
    ld (rub_rows),a
    ld l,(ix+0)                 ; x
    ld h,(ix+1)
    ld (rub_x),hl
    ld a,(ix+2)                 ; y
    ld (rub_y),a
    ld (rub_from),a             ; source bits 7:0 = y
    ld a,l
    ld (rub_from+1),a           ; bits 15:8 = x bits 7:0
    ld a,h
    add a,BACK_AT>>16
    ld (rub_from_hi),a          ; bits 23:16 = $09 + x bit 8
    ld hl,rub_one
    ld bc,(rub_one_end-rub_one)*256+DMA
    otir
    pop bc
.skip:
    ld de,6
    add ix,de
    djnz .next
    ret

rub_setup:
    db $83,$C3                  ; stop, reset
    db $54,$02                  ; WR1: memory, increment, 2-cycle timing
    db $50,$02                  ; WR2: memory, increment, 2-cycle timing
                                ; (checked on issue 5; if a board shows
                                ; wrong pixels, use $14,$10 for the default)
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $EB : dw 256             ; port A stride: the background's next column
rub_setup_end:

rub_one:
    db $1D                      ; WR0: A to B, port A address
rub_from:
    dw 0
    db $D7                      ; port A bits 23:16
rub_from_hi:
    db 0
    db $E3                      ; row length: the rows drawn
rub_rows:
    dw 0
    db $E7                      ; rows: the columns drawn
rub_cols:
    dw 0
    db $DF,PHYSICAL|TWO_D|XY|HIDDEN
rub_x:
    dw 0
rub_y:
    db 0
    db $CF,$87                  ; load, go
rub_one_end:

; -----------------------------------------------------------------------------
; 2. Move the balls, wrapping round the edges, then clip each one and note
; what to draw on the screen being drawn.
;
; Each ball: x (2 bytes), y (2 bytes), dx, dy. x runs from -16 to 319 and y
; from -16 to 255, so a ball leaves one edge completely before it comes back
; in at the other.
; -----------------------------------------------------------------------------
move:
    ld ix,balls
    ld iy,(where_drawn)
    ld b,NUM
.next:
    push bc
    ld l,(ix+0)                 ; x = x + dx
    ld h,(ix+1)
    ld a,(ix+4)
    call add_signed
    ld bc,336                   ; keep x in -16 to 319
    call wrap
    ld (ix+0),l
    ld (ix+1),h
    push hl                     ; keep x

    ld l,(ix+2)                 ; y = y + dy
    ld h,(ix+3)
    ld a,(ix+5)
    call add_signed
    ld bc,272                   ; keep y in -16 to 255
    call wrap
    ld (ix+2),l
    ld (ix+3),h
    ex de,hl                    ; DE = y
    pop hl                      ; HL = x

    call clip                   ; note what shows, if any
    ld (iy+3),0
    jr c,.noted
    ld hl,(clip_x)
    ld (iy+0),l
    ld (iy+1),h
    ld a,(clip_y)
    ld (iy+2),a
    ld a,(clip_cols)
    ld (iy+3),a
    ld a,(clip_rows)
    ld (iy+4),a
    ld a,(clip_off)
    ld (iy+5),a
.noted:
    ld de,6
    add ix,de
    add iy,de
    pop bc
    djnz .next
    ret

; HL = HL + A, with A signed
add_signed:
    ld e,a
    rla
    sbc a,a
    ld d,a
    add hl,de
    ret

; Wrap HL into -16 to BC-17: add or take away BC (336 for x, 272 for y)
wrap:
    ld de,16                    ; HL + 16 should be 0 to BC-1
    add hl,de
    bit 7,h
    jr z,.not_below
    add hl,bc                   ; below: add BC
    jr .done
.not_below:
    or a
    sbc hl,bc                   ; BC or more: take BC away
    jr nc,.done
    add hl,bc                   ; less: put it back
.done:
    ld de,-16
    add hl,de
    ret

; -----------------------------------------------------------------------------
; Clip a 16x16 ball at (HL, DE), both signed.
; Out: carry set if none of it is on the screen. Otherwise clip_x, clip_y
; (where to draw), clip_cols, clip_rows (how much) and clip_off (where to
; start in the picture).
; -----------------------------------------------------------------------------
clip:
    ld c,0                      ; C = c0, the columns skipped
    ld a,SIZE                   ; A = columns shown
    bit 7,h
    jr z,.x_right
    ld a,l                      ; x < 0: skip -x columns
    neg
    cp SIZE
    ccf
    ret c                       ; all of it is off the left
    ld c,a
    ld a,SIZE
    sub c
    ld hl,0                     ; and draw from x = 0
    jr .x_done
.x_right:
    dec h                       ; x of 256 or more?
    inc h
    jr z,.x_done
    ld a,l                      ; x of 304 to 319: 320 - x columns show
    cp 320-SIZE-256
    ld a,SIZE
    jr c,.x_done
    ld a,320-256
    sub l
.x_done:
    ld (clip_x),hl
    ld (clip_cols),a

    ld b,0                      ; B = r0, the rows skipped
    ld a,SIZE                   ; A = rows shown
    bit 7,d
    jr z,.y_down
    ld a,e                      ; y < 0: skip -y rows
    neg
    cp SIZE
    ccf
    ret c                       ; all of it is off the top
    ld b,a
    ld a,SIZE
    sub b
    ld e,0                      ; and draw from y = 0
    jr .y_done
.y_down:
    ld a,e                      ; y of 240 to 255: 256 - y rows show
    cp 256-SIZE
    ld a,SIZE
    jr c,.y_done
    ld a,e
    neg
.y_done:
    ld (clip_rows),a
    ld a,e
    ld (clip_y),a

    ld a,c                      ; offset = c0 * 16 + r0
    add a,a
    add a,a
    add a,a
    add a,a
    add a,b
    ld (clip_off),a
    or a                        ; carry clear: something shows
    ret

clip_x:
    dw 0
clip_y:
    db 0
clip_cols:
    db 0
clip_rows:
    db 0
clip_off:
    db 0

; -----------------------------------------------------------------------------
; 3. Draw the part of each ball that shows, skipping the transparent byte
; -----------------------------------------------------------------------------
draw:
    ld hl,draw_setup            ; the rub-out set-up is still there,
    ld bc,(draw_setup_end-draw_setup)*256+DMA
    otir                        ; so only these settings change
    ld ix,(where_drawn)
    ld b,NUM
.next:
    ld a,(ix+3)                 ; nothing to draw?
    or a
    jr z,.skip
    push bc
    ld (draw_cols),a
    ld a,(ix+4)
    ld (draw_rows),a
    ld l,(ix+0)
    ld h,(ix+1)
    ld (draw_x),hl
    ld a,(ix+2)
    ld (draw_y),a
    ld a,(ix+5)                 ; start in the picture
    ld (draw_from),a            ; (the ball starts at $..8000, so the
    ld hl,draw_one              ;  offset is just bits 7:0)
    ld bc,(draw_one_end-draw_one)*256+DMA
    otir
    pop bc
.skip:
    ld de,6
    add ix,de
    djnz .next
    ret

draw_setup:
    db $EB : dw SIZE            ; port A stride: the ball's columns follow on
    db $F3,$E3                  ; transparent byte
    db $D7,BALL_AT>>16          ; port A bits 23:16
draw_setup_end:

draw_one:
    db $1D                      ; WR0: A to B, port A address
draw_from:
    dw BALL_AT&$FFFF
    db $E3                      ; row length: the rows that show
draw_rows:
    dw 0
    db $E7                      ; rows: the columns that show
draw_cols:
    dw 0
    db $DF,PHYSICAL|TWO_D|TRANSPARENT|XY|HIDDEN
draw_x:
    dw 0
draw_y:
    db 0
    db $CF,$87                  ; load, go
draw_one_end:

; -----------------------------------------------------------------------------
; Start the balls in random places, going in random directions
; -----------------------------------------------------------------------------
init_balls:
    ld ix,balls
    ld b,NUM
.next:
    push bc
    call random                 ; x: 0 to 255, y: 0 to 255
    ld (ix+0),l
    ld (ix+1),0
    ld (ix+2),h
    ld (ix+3),0
    call random
    ld a,l                      ; dx: 1 to 3, either way
    and 3
    jr nz,.dx
    inc a
.dx:
    bit 7,l
    jr z,.dx_ok
    neg
.dx_ok:
    ld (ix+4),a
    ld a,h                      ; dy: 1 to 2, either way
    and 1
    inc a
    bit 7,h
    jr z,.dy_ok
    neg
.dy_ok:
    ld (ix+5),a
    ld de,6
    add ix,de
    pop bc
    djnz .next
    ret

; HL = a new random number (16-bit xorshift)
random:
    ld hl,(seed)
    ld a,h
    rra
    ld a,l
    rra
    xor h
    ld h,a
    ld a,l
    rra
    ld a,h
    rra
    xor l
    ld l,a
    xor h
    ld h,a
    ld (seed),hl
    ret

seed:
    dw 1

; -----------------------------------------------------------------------------
; The background: eight bars with black lines across, drawn with fill mode
; into the screen in NextReg $12 (here the background bank)
; -----------------------------------------------------------------------------
draw_background:
    ld ix,background
    ld b,(background_end-background)/8
.next:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (box_x),hl
    ld a,(ix+2)
    ld (box_y),a
    ld l,(ix+3)                 ; rows = width
    ld h,(ix+4)
    ld (box_w),hl
    ld l,(ix+5)                 ; row length = height
    ld h,(ix+6)
    ld (box_h),hl
    ld a,(ix+7)
    ld (box_colour),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ld de,8
    add ix,de
    pop bc
    djnz .next
    ret

    macro BOX x,y,w,h,colour
        dw x
        db y
        dw w,h
        db colour
    endm

background:
    BOX   0,0,40,256,$E0        ; eight bars
    BOX  40,0,40,256,$F4
    BOX  80,0,40,256,$FC
    BOX 120,0,40,256,$1C
    BOX 160,0,40,256,$1F
    BOX 200,0,40,256,$03
    BOX 240,0,40,256,$A2
    BOX 280,0,40,256,$6D
    BOX 0, 12,320,8,$00         ; black lines across
    BOX 0, 44,320,8,$00
    BOX 0, 76,320,8,$00
    BOX 0,108,320,8,$00
    BOX 0,140,320,8,$00
    BOX 0,172,320,8,$00
    BOX 0,204,320,8,$00
    BOX 0,236,320,8,$00
background_end:

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length: the height
box_h:
    dw 0
    db $E7                      ; rows: the width
box_w:
    dw 0
    db $F7                      ; fill value: the colour
box_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL|XY
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

; Copy the whole background (80K) to a screen
; In: A = screen address bits 23:16, HL = bits 15:0
copy_background:
    ld (copy_to_hi),a
    ld (copy_to),hl
    ld hl,copy_dma
    ld bc,(copy_dma_end-copy_dma)*256+DMA
    otir
    ret

copy_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw BACK_AT&$FFFF
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
copy_to:
    dw 0
    db $82                      ; WR5: stop at the end
    db $D7,BACK_AT>>16          ; port A bits 23:16
    db $DB                      ; port B bits 23:16
copy_to_hi:
    db 0
    db $E3 : dw 16384           ; 5 rows of 16K: 80K in one go
    db $E7 : dw 5
    db $EB : dw 16384
    db $EF : dw 16384
    db $DF,PHYSICAL|TWO_D
    db $CF,$87                  ; load, go
copy_dma_end:

; -----------------------------------------------------------------------------
; The balls, and what is drawn on screen A and on screen B
; -----------------------------------------------------------------------------
balls:
    ds NUM*6
where_a:
    ds NUM*6
where_b:
    ds NUM*6

; -----------------------------------------------------------------------------
; The ball, in 8K page 60. Layer 2 320x256 wants it column by column. This
; ball is the same either way round, so the lines below can be read as rows.
; -----------------------------------------------------------------------------
    mmu 6,BALL_PAGE,$C000
ball:
    db $E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3,$E3
    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3
    db $E3,$E0,$E0,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3
    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3
    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3
    db $E3,$E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3

    savenex open "zxnddma_clip.nex",start,$BFFE
    savenex core 3,2,21
    savenex auto
    savenex close


3.7  zxnddma_lemmings.asm
-------------------------
100 animated lemmings from a sprite sheet, walking both ways.

; =============================================================================
; zxnDDMA lemmings
;
; 100 lemmings walk along six ledges on a Layer 2 320x256 screen. They are
; software sprites: the zxnDDMA draws them, double buffered, like the balls in
; zxnddma_sprites.asm. This time each lemming has its own animation frame and
; direction, so each one is drawn from a different picture.
;
; Assemble with:
;     sjasmplus zxnddma_lemmings.asm
; and run zxnddma_lemmings.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; The pictures come from lem_walk.png: 7 frames of 12x12, walking right. The
; same 7 are stored again mirrored, for walking left. Colours:
;   light blue background -> $E3 (the transparent byte, never drawn)
;   hair (0,176,176)      -> $16
;   skin (240,208,208)    -> $FA
;   body (64,64,224)      -> $4B
;
; How it works:
;   - Two screens, A (bank 9) and B (bank 14). One is shown (NextReg $12)
;     while the other is drawn (NextReg $13). They swap at line 224, just
;     below the picture.
;   - A clean copy of the background lives in bank 20. It is never shown.
;   - Each frame, on the screen being drawn:
;       1. Rub out each lemming: copy back the 12x12 of background where it
;          was on this screen, two frames ago.
;       2. Every third frame (about 17 times a second, as in the game), each
;          lemming steps one pixel and moves on to its next picture. At the
;          edge of the screen it turns round.
;       3. Draw each lemming from its picture, skipping the transparent byte.
;   - Steps 1 and 3 use the X,Y form of $DF with the HIDDEN flag, so the DMA
;     works out the address in the screen in NextReg $13 itself.
;
; Things to know:
;   - Layer 2 320x256 is stored column by column, so the pictures are too:
;     each line of 12 bytes at the end of this file is one column, top to
;     bottom. A DMA "row" is one of those columns.
;   - 16K bank n is at physical address $40000 + n * $4000, and 8K page n at
;     $40000 + n * $2000.
;   - Every setting stays until $C3. After one set-up a frame, each lemming
;     needs 12 bytes to rub out and 10 to draw: its picture, its X,Y, then
;     $CF $87.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B
NUM         equ 100             ; number of lemmings (up to 255)
                                ; 100 lemmings use 160 of the 312 lines
                                ; in a 50Hz frame (1.6 lines each).
                                ; Measured on an issue 5 at 28MHz.
SIZE        equ 12              ; each picture is 12x12

SCREEN_A    equ 9               ; 16K banks
SCREEN_B    equ 14
BACKGROUND  equ 20
LEM_PAGE    equ 60              ; 8K page

SCREEN_A_AT equ $40000+SCREEN_A*$4000      ; $064000
SCREEN_B_AT equ $40000+SCREEN_B*$4000      ; $078000
BACK_AT     equ $40000+BACKGROUND*$4000    ; $090000
LEM_AT      equ $40000+LEM_PAGE*$2000      ; $0B8000

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows
HIDDEN      equ %00100000       ; with XY: the screen in NextReg $13

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $69,0               ; Layer 2 off while we set up
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $1C,1               ; open the Layer 2 clip window
    nextreg $18,0
    nextreg $18,159
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off

    nextreg $12,BACKGROUND      ; draw the background in bank 20 with X,Y
    call draw_background
    ld a,SCREEN_A_AT>>16        ; then copy it to both screens
    ld hl,SCREEN_A_AT&$FFFF
    call copy_background
    ld a,SCREEN_B_AT>>16
    ld hl,SCREEN_B_AT&$FFFF
    call copy_background

    nextreg $12,SCREEN_A        ; shown
    nextreg $13,SCREEN_B        ; drawn
    call init_lemmings
    nextreg $69,%10000000       ; Layer 2 on

frame:
    call wait_bottom
    call swap_screens
    call rub_out
    call walk
    call draw
    jr frame

; -----------------------------------------------------------------------------
; Wait for line 224, just below the bottom of the 320x256 picture
; -----------------------------------------------------------------------------
wait_bottom:
    ld bc,$243B                 ; select NextReg $1F, the video line
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.out:
    in a,(c)                    ; if we are on line 224 already, let it end
    cp 224
    jr z,.out
.in:
    in a,(c)
    cp 224
    jr nz,.in
    ret

; -----------------------------------------------------------------------------
; Show the screen we have just drawn, and draw on the other one
; -----------------------------------------------------------------------------
swap_screens:
    ld a,(shown)
    ld b,a
    ld a,(drawn)
    ld (shown),a
    nextreg $12,a
    ld a,b
    ld (drawn),a
    nextreg $13,a
    ld hl,(where_shown)         ; and swap their lists of lemmings
    ld de,(where_drawn)
    ld (where_shown),de
    ld (where_drawn),hl
    ret

shown:
    db SCREEN_A
drawn:
    db SCREEN_B
where_shown:
    dw where_a                  ; what is drawn where, on each screen
where_drawn:
    dw where_b

; -----------------------------------------------------------------------------
; 1. Rub out: copy 12x12 of background back over each lemming
;
; The background is laid out like a screen, so the square at (x,y) starts at
; BACK_AT + x * 256 + y.
; -----------------------------------------------------------------------------
rub_out:
    ld hl,rub_setup
    ld bc,(rub_setup_end-rub_setup)*256+DMA
    otir
    ld ix,(where_drawn)
    ld b,NUM
.next:
    push bc
    ld l,(ix+0)                 ; x
    ld h,(ix+1)
    ld (rub_x),hl
    ld a,(ix+2)                 ; y
    ld (rub_y),a
    ld (rub_from),a             ; source bits 7:0 = y
    ld a,l
    ld (rub_from+1),a           ; bits 15:8 = x bits 7:0
    ld a,h
    add a,BACK_AT>>16
    ld (rub_from_hi),a          ; bits 23:16 = $09 + x bit 8
    ld hl,rub_one
    ld bc,(rub_one_end-rub_one)*256+DMA
    otir
    ld de,5
    add ix,de
    pop bc
    djnz .next
    ret

rub_setup:
    db $83,$C3                  ; stop, reset
    db $54,$02                  ; WR1: memory, increment, 2-cycle timing
    db $50,$02                  ; WR2: memory, increment, 2-cycle timing
                                ; (checked on issue 5; if a board shows
                                ; wrong pixels, use $14,$10 for the default)
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3 : dw SIZE            ; row length: a column of 12 pixels
    db $E7 : dw SIZE            ; rows: 12 columns
    db $EB : dw 256             ; port A stride: the background's next column
rub_setup_end:

rub_one:
    db $1D                      ; WR0: A to B, port A address
rub_from:
    dw 0
    db $D7                      ; port A bits 23:16
rub_from_hi:
    db 0
    db $DF,PHYSICAL|TWO_D|XY|HIDDEN
rub_x:
    dw 0
rub_y:
    db 0
    db $CF,$87                  ; load, go
rub_one_end:

; -----------------------------------------------------------------------------
; 2. Walk: every third frame each lemming takes a step. Then note, for the
; screen being drawn, where it goes and which picture it uses.
;
; Each lemming: x (2 bytes), y, dx (+1 right, -1 left), frame (0-6)
; Each note:    x (2 bytes), y, picture address (bits 15:0)
; -----------------------------------------------------------------------------
walk:
    ld a,(tick)                 ; count 0, 1, 2, 0, 1, 2 ...
    inc a
    cp 3
    jr c,.tick
    xor a
.tick:
    ld (tick),a
    ld ix,lemmings
    ld iy,(where_drawn)
    ld b,NUM
.next:
    ld a,(tick)
    or a
    jr nz,.note                 ; no step this frame

    ld a,(ix+4)                 ; next frame of the walk
    inc a
    cp 7
    jr c,.frame
    xor a
.frame:
    ld (ix+4),a

    ld l,(ix+0)                 ; x = x + dx
    ld h,(ix+1)
    ld a,(ix+3)
    ld e,a
    rla
    sbc a,a
    ld d,a
    add hl,de
    ld a,h                      ; 0 to 307 is fine
    cp 1
    jr c,.x_ok
    ld a,l
    cp 320-SIZE-256
    jr c,.x_ok
    ld a,(ix+3)                 ; at the edge: turn round, stay put
    neg
    ld (ix+3),a
    ld l,(ix+0)
    ld h,(ix+1)
.x_ok:
    ld (ix+0),l
    ld (ix+1),h

.note:
    ld a,(ix+0)                 ; where
    ld (iy+0),a
    ld a,(ix+1)
    ld (iy+1),a
    ld a,(ix+2)
    ld (iy+2),a
    ld a,(ix+4)                 ; which picture: the frame,
    bit 7,(ix+3)
    jr z,.right
    add a,7                     ; plus 7 when walking left
.right:
    add a,a
    ld e,a
    ld d,0
    ld hl,pictures
    add hl,de
    ld a,(hl)
    ld (iy+3),a
    inc hl
    ld a,(hl)
    ld (iy+4),a

    ld de,5
    add ix,de
    add iy,de
    djnz .next
    ret

tick:
    db 0

; Bits 15:0 of each picture's address: 7 walking right, then 7 walking left
pictures:
N = 0
    dup 14
    dw (LEM_AT&$FFFF)+N*SIZE*SIZE
N = N+1
    edup

; -----------------------------------------------------------------------------
; 3. Draw the lemmings, skipping the transparent byte
; -----------------------------------------------------------------------------
draw:
    ld hl,draw_setup            ; the rub-out set-up is still there,
    ld bc,(draw_setup_end-draw_setup)*256+DMA
    otir                        ; so only these settings change
    ld ix,(where_drawn)
    ld b,NUM
.next:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (draw_x),hl
    ld a,(ix+2)
    ld (draw_y),a
    ld l,(ix+3)
    ld h,(ix+4)
    ld (draw_from),hl
    ld hl,draw_one
    ld bc,(draw_one_end-draw_one)*256+DMA
    otir
    ld de,5
    add ix,de
    pop bc
    djnz .next
    ret

draw_setup:
    db $EB : dw SIZE            ; port A stride: a picture's columns follow on
    db $F3,$E3                  ; transparent byte
    db $D7,LEM_AT>>16           ; port A bits 23:16: all pictures are in here
draw_setup_end:

draw_one:                       ; 10 bytes a lemming
    db $1D                      ; WR0: A to B, port A address: the picture
draw_from:
    dw 0
    db $DF,PHYSICAL|TWO_D|TRANSPARENT|XY|HIDDEN
draw_x:
    dw 0
draw_y:
    db 0
    db $CF,$87                  ; load, go
draw_one_end:

; -----------------------------------------------------------------------------
; Start each lemming on a random ledge, place, direction and frame
; -----------------------------------------------------------------------------
init_lemmings:
    ld ix,lemmings
    ld iy,where_a
    ld b,NUM
.next:
    push bc
    call random                 ; x: 0 to 511, folded into 0 to 307
    ld a,h
    and 1
    ld h,a
    jr z,.x_ok
    ld a,l
    cp 320-SIZE-256
    jr c,.x_ok
    ld h,0
.x_ok:
    ld (ix+0),l
    ld (ix+1),h
    ld (iy+0),l                 ; screen A has nothing to rub out yet,
    ld (iy+1),h                 ; so any position will do

    call random                 ; which ledge: 0 to 5
    ld a,l
    and 7
    cp 6
    jr c,.ledge
    sub 3
.ledge:
    ld e,a
    ld d,0
    ld hl,ledge_y
    add hl,de
    ld a,(hl)
    ld (ix+2),a
    ld (iy+2),a

    call random
    ld a,1                      ; dx: +1 or -1
    bit 0,h
    jr z,.dx
    neg
.dx:
    ld (ix+3),a
    ld a,l                      ; frame: 0 to 6
    and 7
    cp 7
    jr c,.frame
    xor a
.frame:
    ld (ix+4),a

    ld de,5
    add ix,de
    add iy,de
    pop bc
    djnz .next
    ld hl,where_a               ; the same for screen B
    ld de,where_b
    ld bc,NUM*5
    ldir
    ret

; y of a lemming standing on each ledge (the feet are on picture row 9)
ledge_y:
    db 48-10,88-10,128-10,168-10,208-10,248-10

; HL = a new random number (16-bit xorshift)
random:
    ld hl,(seed)
    ld a,h
    rra
    ld a,l
    rra
    xor h
    ld h,a
    ld a,l
    rra
    ld a,h
    rra
    xor l
    ld l,a
    xor h
    ld h,a
    ld (seed),hl
    ret

seed:
    dw 1

; -----------------------------------------------------------------------------
; The background: a dark sky and six ledges, drawn with fill mode into the
; screen in NextReg $12 (here the background bank)
; -----------------------------------------------------------------------------
draw_background:
    ld ix,background
    ld b,(background_end-background)/8
.next:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (box_x),hl
    ld a,(ix+2)
    ld (box_y),a
    ld l,(ix+3)                 ; rows = width
    ld h,(ix+4)
    ld (box_w),hl
    ld l,(ix+5)                 ; row length = height
    ld h,(ix+6)
    ld (box_h),hl
    ld a,(ix+7)
    ld (box_colour),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ld de,8
    add ix,de
    pop bc
    djnz .next
    ret

    macro BOX x,y,w,h,colour
        dw x
        db y
        dw w,h
        db colour
    endm

    macro LEDGE y
        BOX 0,y,320,2,$34       ; grass
        BOX 0,y+2,320,6,$A4     ; earth
    endm

background:
    BOX 0,  0,320,32,$00        ; the sky, dark at the top
    BOX 0, 32,320,32,$01
    BOX 0, 64,320,32,$02
    BOX 0, 96,320,32,$22
    BOX 0,128,320,32,$23
    BOX 0,160,320,32,$43
    BOX 0,192,320,32,$63
    BOX 0,224,320,32,$83
    LEDGE 48
    LEDGE 88
    LEDGE 128
    LEDGE 168
    LEDGE 208
    LEDGE 248
background_end:

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length: the height
box_h:
    dw 0
    db $E7                      ; rows: the width
box_w:
    dw 0
    db $F7                      ; fill value: the colour
box_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL|XY
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

; Copy the whole background (80K) to a screen
; In: A = screen address bits 23:16, HL = bits 15:0
copy_background:
    ld (copy_to_hi),a
    ld (copy_to),hl
    ld hl,copy_dma
    ld bc,(copy_dma_end-copy_dma)*256+DMA
    otir
    ret

copy_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw BACK_AT&$FFFF
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
copy_to:
    dw 0
    db $82                      ; WR5: stop at the end
    db $D7,BACK_AT>>16          ; port A bits 23:16
    db $DB                      ; port B bits 23:16
copy_to_hi:
    db 0
    db $E3 : dw 16384           ; 5 rows of 16K: 80K in one go
    db $E7 : dw 5
    db $EB : dw 16384
    db $EF : dw 16384
    db $DF,PHYSICAL|TWO_D
    db $CF,$87                  ; load, go
copy_dma_end:

3.8  zxnddma_modes.asm
----------------------
One box routine and one ball routine in 256x192, 320x256 and 640x256.

; =============================================================================
; zxnDDMA in all three Layer 2 modes
;
; The same picture - a panel, six balls, eight colour bars and two lines of
; text - drawn in 256x192, then 320x256, then 640x256, four seconds each,
; round and round. The same box and ball routines draw it every time.
;
; Assemble with:
;     sjasmplus zxnddma_modes.asm
; and run zxnddma_modes.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; The X,Y form of $DF works out the address in whichever mode NextReg $70
; says. What changes from mode to mode is what a DMA "row" is:
;
;   256x192   row-major. A row is a row: the row length is the width and the
;             number of rows is the height.
;   320x256   column-major. A row is a column: the row length is the height
;             and the number of rows is the width.
;   640x256   column-major, 4 bits a pixel, so a byte is 2 pixels side by
;             side. X counts bytes (0-319), not pixels. The row length is
;             the height and the number of rows is the width / 2.
;
; In all three the port B stride is 256 (the X,Y form sets it): the next row
; in 256x192, the next column in the other two.
;
; Things to know:
;   - 640x256 has 16 colours. Here they come from the second Layer 2 palette,
;     chosen to match the 8-bit picture, so all three modes look the same.
;   - In 640x256 the ball is 16 bytes wide: 32 of those narrow pixels, the
;     same size on the screen as the 16-pixel ball in 320x256. Its colours
;     are 4-bit, two to a byte, so each narrow pixel has its own colour: its
;     red rim is one narrow pixel wide at the sides (half as thick as in
;     320x256) and its highlight is rounder.
;   - But the transparent byte ($00 here) is skipped a byte at a time, so the
;     ball's outline against the background can only step 2 pixels at a
;     time. Edges that step 1 pixel need each byte read, changed and written
;     back: a job for the CPU, not a straight copy.
;   - 256x192 uses 48K (banks 9-11); the other two use 80K (banks 9-13).
;   - The text is drawn by the CPU, a pixel at a time, in each mode's layout.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B
SCREEN      equ 9               ; 16K bank 9: 8K pages 18 on
SCREEN_PAGE equ SCREEN*2

ROWS        equ 0               ; kinds of mode: 256x192
COLUMNS     equ 1               ; 320x256
BYTES       equ 2               ; 640x256

; colours: 8-bit, and the 4-bit colour number in the second palette
BG_8        equ $02
BG_4        equ 1
PANEL_8     equ $25
PANEL_4     equ 2
TEXT_8      equ $FF
TEXT_4      equ 14

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $54,4               ; this program: bank 2 in slots 4 and 5
    nextreg $55,5
    nextreg $12,SCREEN
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $15,0               ; Layer 2 above the ULA, sprites off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette

    nextreg $43,%01010000       ; and the 16 colours for 640x256, in the
    nextreg $40,0               ; second Layer 2 palette
    ld hl,colours_4
    ld b,16
.palette_4:
    ld a,(hl)
    nextreg $44,a
    ld c,a
    srl a
    or c
    and 1
    nextreg $44,a
    inc hl
    djnz .palette_4

main:
    ld ix,modes
    ld b,3
.mode:
    push bc
    push ix
    call show_mode
    ld b,200                    ; 4 seconds
    call wait_frames
    pop ix
    pop bc
    ld de,mode_size
    add ix,de
    djnz .mode
    jr main

; The 16 colours for 640x256 (RRRGGGBB): the same as the 8-bit picture uses
colours_4:
    db $00                      ;  0: black (the ball's transparent byte)
    db BG_8,PANEL_8             ;  1, 2: background, panel
    db $E0,$F4,$FC,$1C          ;  3-10: the bars
    db $1F,$03,$A2,$FF
    db $FC,$E0,$FF              ; 11-13: the ball: yellow, red, white
    db TEXT_8,$6D               ; 14, 15: text, spare

; -----------------------------------------------------------------------------
; The three modes
; -----------------------------------------------------------------------------
    macro MODE nr70, kind, width, height, x2, y2, line1, line2, palette
        db nr70, kind
        dw width, height
        db x2, y2
        dw line1, line2
        db palette
    endm

modes:
    MODE %00000000, ROWS,    256, 192, 255, 191, text_256a, text_256b, %00010000
mode_size equ $-modes
    MODE %00010000, COLUMNS, 320, 256, 159, 255, text_320a, text_320b, %00010000
    MODE %00100000, BYTES,   640, 256, 159, 255, text_640a, text_640b, %00010100

text_256a:  db "256X192: ROWS ARE ROWS",0
text_256b:  db "ROW LENGTH = WIDTH",0
text_320a:  db "320X256: ROWS ARE COLUMNS",0
text_320b:  db "ROW LENGTH = HEIGHT",0
text_640a:  db "640X256: ROWS ARE COLUMNS",0
text_640b:  db "X COUNTS BYTES, 2 PIXELS EACH",0

kind:
    db 0
width:
    dw 0
height:
    dw 0

; -----------------------------------------------------------------------------
; Switch to the mode at IX and draw the picture
; -----------------------------------------------------------------------------
show_mode:
    nextreg $69,0               ; Layer 2 off while it is drawn
    ld a,(ix+0)
    nextreg $70,a               ; the mode
    ld a,(ix+1)
    ld (kind),a
    ld l,(ix+2)
    ld h,(ix+3)
    ld (width),hl
    ld l,(ix+4)
    ld h,(ix+5)
    ld (height),hl
    nextreg $1C,1               ; the clip window (X counts 2 pixels in the
    nextreg $18,0               ; 320 and 640 modes)
    ld a,(ix+6)
    nextreg $18,a
    nextreg $18,0
    ld a,(ix+7)
    nextreg $18,a
    ld a,(ix+12)                ; which palette Layer 2 uses
    nextreg $43,a

    ; the background: the whole screen
    ld hl,0
    ld (bx),hl
    xor a
    ld (by),a
    ld hl,(width)
    ld (bw),hl
    ld hl,(height)
    ld (bh),hl
    ld a,BG_8
    ld (bc8),a
    ld a,BG_4
    ld (bc4),a
    call box

    ; the panel: 8 in from the sides, from 28 down to 28 up
    ld hl,8
    ld (bx),hl
    ld a,28
    ld (by),a
    ld hl,(width)
    ld de,-16
    add hl,de
    ld (bw),hl
    ld hl,(height)
    ld de,-56
    add hl,de
    ld (bh),hl
    ld a,PANEL_8
    ld (bc8),a
    ld a,PANEL_4
    ld (bc4),a
    call box

    ; the eight bars along the bottom, each width / 8
    ld hl,(width)
    srl h
    rr l
    srl h
    rr l
    srl h
    rr l
    ld (bw),hl
    ld hl,16
    ld (bh),hl
    ld a,(height)               ; y = height - 24 (256 - 24 comes out
    sub 24                      ; right in 8 bits too)
    ld (by),a
    ld hl,0
    ld (bx),hl
    ld iy,bar_colours
    ld b,8
.bar:
    push bc
    ld a,(iy+0)
    ld (bc8),a
    ld a,(iy+1)
    ld (bc4),a
    call box
    ld hl,(bx)
    ld de,(bw)
    add hl,de
    ld (bx),hl
    inc iy
    inc iy
    pop bc
    djnz .bar

    ; six balls across the middle
    ld hl,(height)              ; y = height / 2 - 8
    srl h
    rr l
    ld a,l
    sub 8
    ld (by),a
    ld a,(kind)                 ; ball width: 16, or 32 in 640x256
    cp BYTES
    ld hl,16
    jr nz,.wide
    ld hl,32
.wide:
    ld (ball_w),hl
    ld d,h                      ; step = ball width * 3 / 2
    ld e,l
    srl d
    rr e
    add hl,de
    ld (ball_step),hl
    ld de,(ball_w)              ; x = (width - (6 * step - ball width / 2)) / 2
    srl d
    rr e
    ld hl,(ball_step)
    ld b,h
    ld c,l
    add hl,hl                   ; 2
    add hl,bc                   ; 3
    add hl,hl                   ; 6
    or a
    sbc hl,de
    ex de,hl
    ld hl,(width)
    or a
    sbc hl,de
    srl h
    rr l
    ld (bx),hl
    ld b,6
.ball:
    push bc
    call ball
    ld hl,(bx)
    ld de,(ball_step)
    add hl,de
    ld (bx),hl
    pop bc
    djnz .ball

    ; the text
    ld hl,8
    ld e,4
    ld c,(ix+8)
    ld b,(ix+9)
    call print
    ld hl,8
    ld e,14
    ld c,(ix+10)
    ld b,(ix+11)
    call print

    nextreg $69,%10000000       ; Layer 2 on
    ret

bar_colours:                    ; 8-bit, then 4-bit
    db $E0,3, $F4,4, $FC,5, $1C,6, $1F,7, $03,8, $A2,9, $FF,10
ball_w:
    dw 0
ball_step:
    dw 0

; -----------------------------------------------------------------------------
; A box, with fill mode at X,Y: bx, by, bw, bh in pixels, colour bc8 (or bc4
; in 640x256). The only part that depends on the mode is the four lines that
; choose the row length and the number of rows.
; -----------------------------------------------------------------------------
box:
    ld hl,(bx)
    ld de,(bw)
    ld bc,(bh)
    ld a,(bc8)
    ld (box_colour),a
    ld a,(kind)
    cp ROWS
    jr nz,.columns
    ld (box_len),de             ; 256x192: row length = width,
    ld (box_rows),bc            ; rows = height
    jr .go
.columns:
    ld (box_len),bc             ; 320x256: row length = height,
    ld (box_rows),de            ; rows = width
    cp BYTES
    jr nz,.go
    srl h                       ; 640x256: X and the width are in bytes,
    rr l                        ; 2 pixels each
    srl d
    rr e
    ld (box_rows),de
    ld a,(bc4)                  ; and the colour is in both halves of a byte
    ld b,a
    add a,a
    add a,a
    add a,a
    add a,a
    or b
    ld (box_colour),a
.go:
    ld (box_x),hl
    ld a,(by)
    ld (box_y),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ret

bx:     dw 0
by:     db 0
bw:     dw 0
bh:     dw 0
bc8:    db 0
bc4:    db 0

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length
box_len:
    dw 0
    db $E7                      ; rows
box_rows:
    dw 0
    db $F7                      ; fill value
box_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL|XY
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

; -----------------------------------------------------------------------------
; A ball at bx, by (pixels), skipping its transparent byte. 16 bytes by 16 in
; every mode: 16x16 pixels in the 8-bit modes, 32x16 in 640x256.
; -----------------------------------------------------------------------------
ball:
    ld hl,(bx)
    ld de,ball_8                ; the 8-bit ball, transparent byte $E3
    ld a,$E3
    ld b,a
    ld a,(kind)
    cp BYTES
    jr nz,.go
    srl h                       ; 640x256: X in bytes
    rr l
    ld de,ball_4                ; the 4-bit ball, transparent byte $00
    ld b,0
.go:
    ld (ball_x),hl
    ld (ball_from),de
    ld a,b
    ld (ball_clear),a
    ld a,(by)
    ld (ball_y),a
    ld hl,ball_dma
    ld bc,(ball_dma_end-ball_dma)*256+DMA
    otir
    ret

ball_dma:
    db $83,$C3                  ; stop, reset
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $1D                      ; WR0: A to B, port A address: the ball
ball_from:
    dw 0
    db $D7,$04                  ; port A bits 23:16: this program, bank 2
    db $E3 : dw 16              ; 16 by 16 bytes in every mode (it is the
    db $E7 : dw 16              ; same either way round)
    db $EB : dw 16              ; port A stride: the ball's next line
    db $F3                      ; transparent byte
ball_clear:
    db 0
    db $DF,PHYSICAL|TWO_D|TRANSPARENT|XY
ball_x:
    dw 0
ball_y:
    db 0
    db $CF,$87                  ; load, go
ball_dma_end:

; -----------------------------------------------------------------------------
; Wait B frames (50 a second), by watching the video line in NextReg $1F
; -----------------------------------------------------------------------------
wait_frames:
    push bc
    ld bc,$243B                 ; select NextReg $1F
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.in:
    in a,(c)                    ; wait for line 192
    cp 192
    jr nz,.in
.out:
    in a,(c)                    ; and for it to end
    cp 192
    jr z,.out
    pop bc
    djnz wait_frames
    ret

; -----------------------------------------------------------------------------
; Text, drawn by the CPU a pixel at a time. In 640x256 each pixel of the font
; is a whole byte (2 pixels), so the text looks the same in every mode.
; In: BC -> zero-ended text, HL = x in pixels, E = y.
; -----------------------------------------------------------------------------
print:
    ld a,(bc)
    or a
    ret z
    push bc
    push hl
    push de
    call print_char
    pop de
    pop hl
    pop bc
    inc bc
    push de                     ; (E is the y)
    ld a,(kind)                 ; next character: 8 pixels on, or 16
    cp BYTES
    ld de,8
    jr nz,.step
    ld de,16
.step:
    add hl,de
    pop de
    jr print

print_char:
    sub 32                      ; DE -> the letter's 8 bytes
    push hl
    ld l,a
    ld h,0
    add hl,hl
    add hl,hl
    add hl,hl
    ld bc,font
    add hl,bc
    ld (glyph),hl
    pop hl
    ld d,0                      ; D = row
.row:
    push hl
    push de
    ld bc,(glyph)
    ld a,c
    add a,d
    ld c,a
    adc a,b
    sub c
    ld b,a
    ld a,(bc)                   ; this row's 8 bits
    ld c,a
    ld b,8
.pixel:
    sla c
    jr nc,.blank
    push bc
    push hl
    push de
    call plot
    pop de
    pop hl
    pop bc
.blank:
    inc hl
    ld a,(kind)                 ; 640x256: each font pixel is 2 pixels
    cp BYTES
    jr nz,.next
    inc hl
.next:
    djnz .pixel
    pop de
    pop hl
    inc e                       ; next row down
    inc d
    ld a,d
    cp 8
    jr nz,.row
    ret

glyph:
    dw 0

; Set pixel HL = x, E = y to the text colour, in the current mode.
; Pages the screen into MMU slot 6.
plot:
    ld a,(kind)
    cp ROWS
    jr nz,.columns
    ld a,e                      ; 256x192: byte y * 256 + x
    rlca                        ; page 18 + y / 32
    rlca
    rlca
    and 7
    add a,SCREEN_PAGE
    nextreg $56,a
    ld a,e
    and 31
    add a,$C0
    ld h,a                      ; at $C000 + (y mod 32) * 256 + x
    ld (hl),TEXT_8
    ret
.columns:
    cp BYTES
    jr z,.bytes
    call column_address         ; 320x256: byte x * 256 + y
    ld (hl),TEXT_8
    ret
.bytes:
    srl h                       ; 640x256: byte (x / 2) * 256 + y,
    rr l                        ; both pixels: the font pixel is doubled
    call column_address
    ld (hl),TEXT_4*$11
    ret

; Page column HL (0-319) into slot 6 and point HL at row E of it
column_address:
    ld a,l                      ; page 18 + x / 32
    and $E0
    or h
    rlca
    rlca
    rlca
    add a,SCREEN_PAGE
    nextreg $56,a
    ld a,l                      ; at $C000 + (x mod 32) * 256 + y
    and 31
    add a,$C0
    ld h,a
    ld l,e
    ret

; -----------------------------------------------------------------------------
; The balls, column by column. The 8-bit one is the same either way round, so
; its lines can be read as rows too - which 256x192 needs. The 4-bit one is
; only for 640x256, which is column by column: each line is one column of
; bytes, and each byte is two narrow pixels (left one in the top 4 bits).
; -----------------------------------------------------------------------------
ball_8:                         ; 8-bit colours, $E3 = transparent
    db $E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3,$E3
    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3
    db $E3,$E0,$E0,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3
    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FF,$FF,$FF,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E3
    db $E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3
    db $E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3
    db $E3,$E3,$E3,$E0,$E0,$FC,$FC,$FC,$FC,$FC,$FC,$E0,$E0,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E0,$E3,$E3,$E3,$E3
    db $E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3,$E3

ball_4:                         ; 4-bit colours, two to a byte, $00 = transparent
    db $00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00
    db $00,$00,$00,$00,$CC,$CB,$CB,$CB,$CB,$CB,$CB,$CC,$00,$00,$00,$00
    db $00,$00,$00,$CC,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$CC,$00,$00,$00
    db $00,$00,$CC,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$CC,$00,$00
    db $00,$CC,$BB,$BB,$DD,$DD,$BD,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$CC,$00
    db $00,$CC,$BB,$BB,$DD,$DD,$DD,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$CC,$00
    db $00,$CC,$BB,$BB,$DD,$DD,$DD,$BB,$BB,$BB,$BB,$BB,$BB,$BB,$CC,$00

3.9  zxnddma_scroll.asm
-----------------------
A scrolling tile map: hardware scroll, the zxnDDMA draws only the new tiles.

; =============================================================================
; zxnDDMA scrolling tile map
;
; A landscape of 16x16 tiles scrolls smoothly across Layer 2 320x256, one
; pixel a frame, for ever. The hardware does the scrolling; the zxnDDMA only
; draws the new column of tiles coming in at the right, once every 16 frames.
;
; Assemble with:
;     sjasmplus zxnddma_scroll.asm
; and run zxnddma_scroll.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; Why not just copy the screen? Moving all 80K every frame takes longer than
; a frame. Layer 2 can scroll itself (NextReg $16, with the top bit in $71):
; display column c shows screen column (c + scroll) mod 320, so nothing has
; to move. What is needed is somewhere to draw the new tiles where they
; can't be seen yet.
;
; The trick: a clip window hides 8 pixels at each side (NextReg $18). So at
; scroll s, screen columns s-8 to s+7 are hidden - 16 columns, the width of a
; tile. When s mod 16 = 8 those 16 columns are exactly one tile wide, so the
; whole next column of tiles (16 of them, top to bottom) is drawn there. Over
; the next 16 frames it slides into view at the right, a column at a time.
;   - Each tile is one zxnDDMA transfer: physical source, X,Y destination.
;   - That's 16 small transfers every 16 frames. The rest of the time the
;     DMA has nothing to do.
;   - The screen is 304 pixels wide on the display, the price of the clip.
;
; The map is 256 tiles wide and 16 high, made at the start: hills of grass and
; earth, clouds and brick ledges. It is stored a column at a time, so one
; column of the map is 16 bytes in a row. The tiles live in 8K page 60 and are
; only read by the DMA, through their physical address.
;
; Things to know:
;   - In 320x256 the clip X values count 2 pixels (X1 = 4 is pixel 8, X2 = 155
;     is pixel 311).
;   - The scroll value goes 0 to 319: the top bit is NextReg $71 bit 0.
;   - 16K bank n is at physical address $40000 + n * $4000, and 8K page n at
;     $40000 + n * $2000.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B
SCREEN      equ 9               ; 16K bank
TILE_PAGE   equ 60              ; 8K page
TILES_AT    equ $40000+TILE_PAGE*$2000     ; $0B8000
MAP_W       equ 256             ; map width in tiles (must be 256 here)

; tiles
SKY         equ 0
CLOUD_L     equ 1
CLOUD_R     equ 2
GRASS       equ 3
EARTH       equ 4
BRICK       equ 5
DEEP        equ 6

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
XY          equ %00010000       ; Layer 2 X,Y destination follows

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $69,0               ; Layer 2 off while we set up
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $12,SCREEN
    nextreg $1C,1               ; clip window: hide 8 pixels each side
    nextreg $18,4               ;   X1: pixel 8
    nextreg $18,155             ;   X2: pixel 311
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off

    call make_map

    ld hl,tile_setup            ; the DMA set-up, once: every tile is the same
    ld bc,(tile_setup_end-tile_setup)*256+DMA  ; shape, so only the source
    otir                        ; and destination change after this

    ld b,20                     ; the first screenful: map columns 0 to 19
    ld de,0                     ; DE = map column, HL = screen column
    ld hl,0
.first:
    push bc
    push de
    push hl
    call draw_column
    pop hl
    pop de
    pop bc
    inc de
    ld a,l
    add a,16
    ld l,a
    adc a,h
    sub l
    ld h,a
    djnz .first

    ld hl,8                     ; start with the scroll at 8
    ld (world),hl
    ld (scroll),hl
    nextreg $69,%10000000       ; Layer 2 on

frame:
    call wait_bottom
    ld hl,(scroll)              ; show this frame's scroll
    ld a,l
    nextreg $16,a
    ld a,h
    nextreg $71,a

    ld a,(world)                ; at 8, 24, 40 ... a new column of tiles
    and 15
    cp 8
    call z,next_column

    ld hl,(world)               ; one pixel on
    inc hl
    ld (world),hl
    ld hl,(scroll)              ; scroll = world mod 320
    inc hl
    ld de,-320
    add hl,de
    jr c,.wrapped
    ld de,320
    add hl,de
.wrapped:
    ld (scroll),hl
    jr frame

world:
    dw 0                        ; how far we have come, in pixels
scroll:
    dw 0                        ; the same, mod 320: the hardware scroll

; The next column of tiles goes into the 16 hidden screen columns, s-8 to s+7.
; It is map column (world - 8) / 16 + 20: the one just off the right edge.
next_column:
    ld hl,(world)
    ld de,-8
    add hl,de
    srl h                       ; / 16
    rr l
    srl h
    rr l
    srl h
    rr l
    srl h
    rr l
    ld de,20
    add hl,de
    ld h,0                      ; mod 256: the map goes round
    ex de,hl                    ; DE = map column
    ld hl,(scroll)              ; HL = screen column s - 8, mod 320
    ld bc,-8
    add hl,bc
    jr c,draw_column
    ld bc,320
    add hl,bc
    ; fall through

; -----------------------------------------------------------------------------
; Draw map column DE (0-255) at screen column HL (0-319): 16 tiles, one zxnDDMA
; transfer each
; -----------------------------------------------------------------------------
draw_column:
    ld (tile_x),hl
    ex de,hl                    ; HL = map + column * 16
    add hl,hl
    add hl,hl
    add hl,hl
    add hl,hl
    ld de,map
    add hl,de
    xor a                       ; y = 0, 16, 32 ... 240
.tile:
    ld (tile_y),a
    ld a,(hl)                   ; the tile: its picture is at TILES_AT +
    add a,high (TILES_AT&$FFFF) ; tile * 256, so only bits 15:8 change
    ld (tile_from+1),a
    push hl
    ld hl,tile_one
    ld bc,(tile_one_end-tile_one)*256+DMA
    otir
    pop hl
    inc hl
    ld a,(tile_y)
    add a,16
    jr nc,.tile                 ; until y goes past 240
    ret

tile_setup:
    db $83,$C3                  ; stop, reset
    db $54,$02                  ; WR1: memory, increment, 2-cycle timing
    db $50,$02                  ; WR2: memory, increment, 2-cycle timing
                                ; (checked on issue 5; if a board shows
                                ; wrong pixels, use $14,$10 for the default)
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $D7,TILES_AT>>16         ; port A bits 23:16: the tiles
    db $E3 : dw 16              ; row length: a column of 16 pixels
    db $E7 : dw 16              ; rows: 16 columns
    db $EB : dw 16              ; port A stride: a tile's columns follow on
tile_setup_end:

tile_one:
    db $1D                      ; WR0: A to B, port A address: the tile
tile_from:
    dw TILES_AT&$FFFF
    db $DF,PHYSICAL|TWO_D|XY
tile_x:
    dw 0
tile_y:
    db 0
    db $CF,$87                  ; load, go
tile_one_end:

; -----------------------------------------------------------------------------
; Wait for line 224, just below the bottom of the 320x256 picture
; -----------------------------------------------------------------------------
wait_bottom:
    ld bc,$243B                 ; select NextReg $1F, the video line
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.out:
    in a,(c)                    ; if we are on line 224 already, let it end
    cp 224
    jr z,.out
.in:
    in a,(c)
    cp 224
    jr nz,.in
    ret

; -----------------------------------------------------------------------------
; Make the map: a column at a time, the ground going up and down at random,
; with clouds in the sky and now and then a brick ledge.
; -----------------------------------------------------------------------------
make_map:
    ld ix,map
    ld b,0                      ; 256 columns
.column:
    push bc
    call random

    ld a,b                      ; the last 16 columns: head back to row 10,
    or a                        ; where column 0 starts, so the map joins
    jr z,.free                  ; up when it goes round
    cp 17
    jr nc,.free
    ld a,(ground)
    cp 10
    jr z,.height_ok
    jr c,.lower
    dec a
    jr .set
.lower:
    inc a
    jr .set
.free:
    ld a,l                      ; one column in four, the ground moves
    and 3
    jr nz,.height_ok
    ld a,(ground)
    bit 2,l
    jr z,.down
    inc a                       ; lower (bigger row number), to row 12
    cp 13
    jr c,.set
    ld a,12
    jr .set
.down:
    dec a                       ; higher, to row 8
    cp 8
    jr nc,.set
    ld a,8
.set:
    ld (ground),a
.height_ok:

    ld a,b                      ; nothing new in the last 4 columns
    dec a
    cp 4
    jr c,.cloud_on
    ld a,(ledge_left)           ; start a ledge? 3 wide, 4 rows up
    or a
    jr nz,.ledge_on
    ld a,h
    and 15
    jr nz,.ledge_on
    ld a,3
    ld (ledge_left),a
.ledge_on:

    ld a,(cloud_next)           ; start a cloud? 2 wide, rows 1 to 4
    or a
    jr nz,.cloud_on
    ld a,h
    and $70
    jr nz,.cloud_on
    ld a,l
    and 3
    inc a
    ld (cloud_row),a
    ld a,CLOUD_L
    ld (cloud_next),a
.cloud_on:

    ld c,0                      ; the 16 rows, top to bottom
.row:
    ld a,(ground)
    cp c
    jr z,.grass
    jr c,.under
    ld a,(cloud_next)           ; sky, maybe a cloud, maybe a ledge
    or a
    jr z,.no_cloud
    ld a,(cloud_row)
    cp c
    jr nz,.no_cloud
    ld a,(cloud_next)
    jr .put
.no_cloud:
    ld a,(ledge_left)
    or a
    jr z,.sky
    ld a,(ground)
    sub 4
    cp c
    jr nz,.sky
    ld a,BRICK
    jr .put
.sky:
    ld a,SKY
    jr .put
.grass:
    ld a,GRASS
    jr .put
.under:
    ld a,(ground)               ; earth for 3 rows, then deep earth
    add a,3
    cp c
    ld a,EARTH
    jr nc,.put
    ld a,DEEP
.put:
    ld (ix+0),a
    inc ix
    inc c
    ld a,c
    cp 16
    jr nz,.row

    ld a,(ledge_left)           ; one column of ledge done
    or a
    jr z,.ledge_done
    dec a
    ld (ledge_left),a
.ledge_done:
    ld a,(cloud_next)           ; left half of a cloud: right half next
    cp CLOUD_L
    ld a,CLOUD_R
    jr z,.cloud_done
    xor a                       ; right half done: no cloud
.cloud_done:
    ld (cloud_next),a

    pop bc
    dec b
    jp nz,.column
    ret

ground:
    db 10                       ; row of the grass in this column
ledge_left:
    db 0                        ; columns of ledge still to make
cloud_next:
    db 0                        ; 0, or the cloud half for this column
cloud_row:
    db 0

; HL = a new random number (16-bit xorshift)
random:
    ld hl,(seed)
    ld a,h
    rra
    ld a,l
    rra
    xor h
    ld h,a
    ld a,l
    rra
    ld a,h
    rra
    xor l
    ld l,a
    xor h
    ld h,a
    ld (seed),hl
    ret

seed:
    dw 1

3.10  zxnddma_windows.asm
-------------------------
A desktop and a window with buttons and a shadow, moved with two copies a
frame.

; =============================================================================
; zxnDDMA windows
;
; A desktop with a menu bar, and a window with a title bar, buttons and a
; drop shadow, gliding about on top of it. Everything is drawn with fill-mode
; boxes, and the window is moved with two copies a frame. For tools and
; utilities as much as games.
;
; Assemble with:
;     sjasmplus zxnddma_windows.asm
; and run zxnddma_windows.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; How it works:
;   - The desktop is drawn once, in bank 20, and never shown. It is the clean
;     copy that goes back where the window was.
;   - The window is drawn once, as a picture, in bank 28. It is 166x118: the
;     window is 160x112 and its shadow sticks out 6 pixels right and down. The
;     two corners the shadow doesn't fill are $E3, the transparent byte, so
;     the desktop shows through there.
;   - Both are drawn with the same box routine, by pointing NextReg $12 (the
;     screen the X,Y form draws on) at bank 20, then bank 28. The text is
;     drawn by the CPU.
;   - Then, double buffered, as in zxnddma_sprites.asm: two screens, A (bank
;     9) and B (bank 14). Each frame, on the screen not being shown:
;       1. copy the desktop back where the window was on this screen,
;       2. move the window,
;       3. copy the window picture there, skipping $E3.
;   - Each copy is one zxnDDMA transfer of 166 x 118 = 19,588 bytes. The two
;     take 109 of the 312 lines in a 50Hz frame (7.0ms), measured on an
;     issue 5 at 28MHz.
;
; Things to know:
;   - The window picture is laid out like a screen (256 bytes a column), so it
;     is copied with a stride of 256 on both sides.
;   - Layer 2 320x256 is stored column by column, so a DMA "row" is a column:
;     the row length is the height (118) and the number of rows the width
;     (166).
;   - 16K bank n is at physical address $40000 + n * $4000. Banks 20 and 28
;     start at $090000 and $0B0000, so bits 15:0 of their start are 0.
;   - A mouse would just set the window's x and y; the drawing is the same.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B

SCREEN_A    equ 9               ; 16K banks
SCREEN_B    equ 14
DESKTOP     equ 20
PICTURE     equ 28

SCREEN_A_AT equ $40000+SCREEN_A*$4000      ; $064000
SCREEN_B_AT equ $40000+SCREEN_B*$4000      ; $078000
DESKTOP_AT  equ $40000+DESKTOP*$4000       ; $090000
PICTURE_AT  equ $40000+PICTURE*$4000       ; $0B0000

WIN_W       equ 160             ; the window
WIN_H       equ 112
SHADOW      equ 6
PIC_W       equ WIN_W+SHADOW    ; the picture: window and shadow
PIC_H       equ WIN_H+SHADOW
TOP         equ 14              ; the window stays below the menu bar

; colours (RRRGGGBB)
BLACK       equ $00
WHITE       equ $FF
GREY        equ $B6
LIGHT       equ $DB
DARK        equ $49
BLUE        equ $03
TEAL_1      equ $12
TEAL_2      equ $0E
CLEAR       equ $E3             ; the transparent byte

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows
HIDDEN      equ %00100000       ; with XY: the screen in NextReg $13

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $54,4               ; this program: bank 2 in slots 4 and 5
    nextreg $55,5
    nextreg $69,0               ; Layer 2 off while we set up
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $1C,1               ; open the Layer 2 clip window
    nextreg $18,0
    nextreg $18,159
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off

    nextreg $12,DESKTOP         ; draw the desktop in bank 20
    ld ix,desktop
    ld b,(desktop_end-desktop)/8
    call boxes
    call checks
    ld a,DESKTOP*2
    ld ix,desktop_text
    call print_list

    nextreg $12,PICTURE         ; draw the window picture in bank 28
    ld ix,window
    ld b,(window_end-window)/8
    call boxes
    ld a,PICTURE*2
    ld ix,window_text
    call print_list

    ld a,SCREEN_A_AT>>16        ; copy the desktop to both screens
    ld hl,SCREEN_A_AT&$FFFF
    call copy_desktop
    ld a,SCREEN_B_AT>>16
    ld hl,SCREEN_B_AT&$FFFF
    call copy_desktop

    nextreg $12,SCREEN_A        ; shown
    nextreg $13,SCREEN_B        ; drawn
    nextreg $69,%10000000       ; Layer 2 on

frame:
    call wait_bottom
    call swap_screens
    call rub_out
    call move
    call draw
    jr frame

; -----------------------------------------------------------------------------
; Wait for line 224, just below the bottom of the 320x256 picture
; -----------------------------------------------------------------------------
wait_bottom:
    ld bc,$243B                 ; select NextReg $1F, the video line
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.out:
    in a,(c)                    ; if we are on line 224 already, let it end
    cp 224
    jr z,.out
.in:
    in a,(c)
    cp 224
    jr nz,.in
    ret

; -----------------------------------------------------------------------------
; Show the screen we have just drawn, and draw on the other one
; -----------------------------------------------------------------------------
swap_screens:
    ld a,(shown)
    ld b,a
    ld a,(drawn)
    ld (shown),a
    nextreg $12,a
    ld a,b
    ld (drawn),a
    nextreg $13,a
    ld hl,(where_shown)         ; and swap where the window is on each:
    ld de,(where_drawn)         ; x
    ld (where_shown),de
    ld (where_drawn),hl
    ld a,(where_shown+2)        ; and y
    ld b,a
    ld a,(where_drawn+2)
    ld (where_shown+2),a
    ld a,b
    ld (where_drawn+2),a
    ret

shown:
    db SCREEN_A
drawn:
    db SCREEN_B
where_shown:
    dw 80                       ; x, and y, of the window on each screen
    db 60                       ; (both screens start without one, and the
where_drawn:                    ; desktop is put back over nothing)
    dw 80
    db 60

; -----------------------------------------------------------------------------
; 1. Put the desktop back where the window was on this screen. The desktop
; is laid out like a screen, so (x,y) in it is at DESKTOP_AT + x * 256 + y.
; -----------------------------------------------------------------------------
rub_out:
    ld hl,(where_drawn)
    ld (rub_x),hl
    ld a,(where_drawn+2)
    ld (rub_y),a
    ld (rub_from),a             ; source bits 7:0 = y
    ld a,l
    ld (rub_from+1),a           ; bits 15:8 = x bits 7:0
    ld a,h
    add a,DESKTOP_AT>>16
    ld (rub_from_hi),a          ; bits 23:16 = $09 + x bit 8
    ld hl,rub_dma
    ld bc,(rub_dma_end-rub_dma)*256+DMA
    otir
    ret

rub_dma:
    db $83,$C3                  ; stop, reset
    db $54,$02                  ; WR1: memory, increment, 2-cycle timing
    db $50,$02                  ; WR2: memory, increment, 2-cycle timing
                                ; (checked on issue 5; if a board shows
                                ; wrong pixels, use $14,$10 for the default)
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3 : dw PIC_H           ; row length: the height
    db $E7 : dw PIC_W           ; rows: the width
    db $EB : dw 256             ; port A stride: the desktop's next column
    db $1D                      ; WR0: A to B, port A address
rub_from:
    dw 0
    db $D7                      ; port A bits 23:16
rub_from_hi:
    db 0
    db $DF,PHYSICAL|TWO_D|XY|HIDDEN
rub_x:
    dw 0
rub_y:
    db 0
    db $CF,$87                  ; load, go
rub_dma_end:

; -----------------------------------------------------------------------------
; 2. Move the window, bouncing off the edges of the desktop
; -----------------------------------------------------------------------------
move:
    ld hl,(win_x)               ; x = x + dx, from 0 to 320 - PIC_W
    ld a,(win_dx)
    ld e,a
    rla
    sbc a,a
    ld d,a
    add hl,de
    bit 7,h
    jr nz,.x_turn
    push hl
    ld de,-(320-PIC_W+1)
    add hl,de
    pop hl
    jr nc,.x_ok
.x_turn:
    ld a,(win_dx)               ; turn round, stay put
    neg
    ld (win_dx),a
    ld hl,(win_x)
.x_ok:
    ld (win_x),hl

    ld a,(win_y)                ; y = y + dy, from TOP to 256 - PIC_H
    ld e,a
    ld a,(win_dy)
    add a,e
    cp TOP
    jr c,.y_turn
    cp 256-PIC_H+1
    jr c,.y_ok
.y_turn:
    ld a,(win_dy)
    neg
    ld (win_dy),a
    ld a,(win_y)
.y_ok:
    ld (win_y),a

    ld hl,(win_x)               ; this is where it goes on this screen
    ld (where_drawn),hl
    ld (where_drawn+2),a
    ret

win_x:
    dw 80
win_y:
    db 60
win_dx:
    db 2
win_dy:
    db 1

; -----------------------------------------------------------------------------
; 3. Copy the window picture there, skipping $E3. The rub-out set-up is still
; there (sizes, the 256 stride), so only the source and the flags change.
; -----------------------------------------------------------------------------
draw:
    ld hl,(where_drawn)
    ld (draw_x),hl
    ld a,(where_drawn+2)
    ld (draw_y),a
    ld hl,draw_dma
    ld bc,(draw_dma_end-draw_dma)*256+DMA
    otir
    ret

draw_dma:
    db $F3,CLEAR                ; transparent byte
    db $1D                      ; WR0: A to B, port A address: the picture
    dw PICTURE_AT&$FFFF
    db $D7,PICTURE_AT>>16       ; port A bits 23:16
    db $DF,PHYSICAL|TWO_D|TRANSPARENT|XY|HIDDEN
draw_x:
    dw 0
draw_y:
    db 0
    db $CF,$87                  ; load, go
draw_dma_end:

; -----------------------------------------------------------------------------
; Copy the whole desktop (80K) to a screen
; In: A = screen address bits 23:16, HL = bits 15:0
; -----------------------------------------------------------------------------
copy_desktop:
    ld (copy_to_hi),a
    ld (copy_to),hl
    ld hl,copy_dma
    ld bc,(copy_dma_end-copy_dma)*256+DMA
    otir
    ret

copy_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw DESKTOP_AT&$FFFF
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
copy_to:
    dw 0
    db $82                      ; WR5: stop at the end
    db $D7,DESKTOP_AT>>16       ; port A bits 23:16
    db $DB                      ; port B bits 23:16
copy_to_hi:
    db 0
    db $E3 : dw 16384           ; 5 rows of 16K: 80K in one go
    db $E7 : dw 5
    db $EB : dw 16384
    db $EF : dw 16384
    db $DF,PHYSICAL|TWO_D
    db $CF,$87                  ; load, go
copy_dma_end:

; -----------------------------------------------------------------------------
; Boxes, drawn with fill mode at X,Y on the screen in NextReg $12
; -----------------------------------------------------------------------------
    macro BOX x,y,w,h,colour
        dw x
        db y
        dw w,h
        db colour
    endm

    ; a raised edge round a box: light top and left, dark bottom and right
    macro BEVEL x,y,w,h
        BOX x,y,w,1,WHITE
        BOX x,y,1,h,WHITE
        BOX x,y+h-1,w,1,DARK
        BOX x+w-1,y,1,h,DARK
    endm

desktop:
    BOX 0,0,320,256,TEAL_1      ; the desktop
    BOX 0,0,320,12,WHITE        ; the menu bar
    BOX 0,12,320,1,BLACK
desktop_end:

window:
    BOX 0,0,PIC_W,PIC_H,CLEAR   ; start see-through
    BOX SHADOW,SHADOW,WIN_W,WIN_H,BLACK ; the shadow
    BOX 0,0,WIN_W,WIN_H,GREY    ; the window
    BEVEL 0,0,WIN_W,WIN_H
    BOX 3,3,WIN_W-6,12,BLUE     ; the title bar
    BOX 6,20,WIN_W-12,56,WHITE  ; a white panel for the text
    BOX 6,20,WIN_W-12,1,DARK    ; sunk in: dark top and left
    BOX 6,20,1,56,DARK
    BOX 20,84,52,18,LIGHT       ; the OK button
    BEVEL 20,84,52,18
    BOX 88,84,58,18,LIGHT       ; the CANCEL button
    BEVEL 88,84,58,18
window_end:

; Draw B boxes from the list at IX
boxes:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (box_x),hl
    ld a,(ix+2)
    ld (box_y),a
    ld l,(ix+3)                 ; rows = width
    ld h,(ix+4)
    ld (box_w),hl
    ld l,(ix+5)                 ; row length = height
    ld h,(ix+6)
    ld (box_h),hl
    ld a,(ix+7)
    ld (box_colour),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ld de,8
    add ix,de
    pop bc
    djnz boxes
    ret

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length: the height
box_h:
    dw 0
    db $E7                      ; rows: the width
box_w:
    dw 0
    db $F7                      ; fill value: the colour
box_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL|XY
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

; The desktop's checks: 32x32 squares of the second colour, every other one
checks:
    ld e,16                     ; y: below the menu bar
.row:
    ld a,e                      ; start on the left, or one square in
    and 32
    ld l,a
    ld h,0
.square:
    ld (check+0),hl
    ld a,e
    ld (check+2),a
    push hl
    push de
    ld ix,check
    ld b,1
    call boxes
    pop de
    pop hl
    ld bc,64
    add hl,bc
    push hl
    ld bc,-320
    add hl,bc
    pop hl
    jr nc,.square
    ld a,e
    add a,32
    ld e,a

    jr c,.row
    ret

check:

; -----------------------------------------------------------------------------
; Text, drawn by the CPU with a 1-bit 8x8 font
; -----------------------------------------------------------------------------

; Print a list of texts on the Layer 2 screen whose first 8K page is A.
; Each entry: x (2 bytes, 0 = the end), y, colour, text, 0
print_list:
    ld (print_page),a
.next:
    ld l,(ix+0)
    ld h,(ix+1)
    ld a,h
    or l
    ret z
    ld e,(ix+2)
    ld a,(ix+3)
    ld (ink),a
    inc ix
    inc ix
    inc ix
    inc ix
    call print                  ; leaves IX on the text's 0
    inc ix
    jr .next

; Print the text at IX (ends with 0) at HL = x, E = y, in colour ink
print:
    ld a,(ix+0)
    or a
    ret z
    push hl
    push de
    call print_char
    pop de
    pop hl
    ld bc,8
    add hl,bc
    inc ix
    jr print

print_char:
    ld (char),a
    call map_xy                 ; HL = screen
    ld a,(char)
    sub 32
    push hl
    ld l,a                      ; DE = the letter's 8 bytes
    ld h,0
    add hl,hl
    add hl,hl
    add hl,hl
    ld de,font
    add hl,de
    ex de,hl
    pop hl
    ld c,$80                    ; C = this column's bit
.col:
    push hl
    push de
    ld b,8
.row:
    ld a,(de)
    and c
    jr z,.blank
    ld a,(ink)
    ld (hl),a
.blank:
    inc de
    inc l
    djnz .row
    pop de
    pop hl
    inc h                       ; next column
    srl c
    jr nc,.col                  ; after 8 columns the bit drops out
    ret

; Page the screen at x into MMU slots 6 and 7, and point at x,y.
; In: HL = x, E = y. Out: HL = the CPU address of x,y (in $C000-$FFFF).
map_xy:
    ld a,l                      ; high byte: $C0 + (x mod 32)
    and 31
    add a,$C0
    ld d,a
    ld a,l                      ; page: first page + x / 32
    and $E0
    or h
    rlca
    rlca
    rlca
    ld hl,print_page
    add a,(hl)
    nextreg $56,a
    inc a
    nextreg $57,a
    ex de,hl                    ; HL = address, E was y
    ret

print_page:
    db 0
ink:
    db 0
char:
    db 0

3.11  zxnddma_scroller.asm
--------------------------
Big letters that flip, a column at a time, or pulse, a row at a time.

; =============================================================================
; zxnDDMA big-letter scroller
;
; A message in 32x32 letters scrolls across a Layer 2 320x256 screen. Every
; 10 seconds it changes between two effects:
;
;   FLIP    each letter turns round on its upright axis, in a wave along the
;           text, showing its metal back half of the time.
;   PULSE   each letter grows and shrinks in height, from 16 to 48 pixels, in
;           a wave along the text.
;
; Assemble with:
;     sjasmplus zxnddma_scroller.asm
; and run zxnddma_scroller.nex on a Next with core 3.03.00 (issue 2, 4 or 5).
; Reset the Next to leave.
;
; zxnDDMA can't stretch a picture in one go, but it can copy one column, or one
; row, at a time, and choosing which column or row goes where is all that
; stretching needs:
;
;   FLIP: one transfer per column on the screen. Each copies one 32-byte
;   column of the letter (row length 32, 1 row). A letter turned part way
;   round is narrower: fewer columns, taken from across the letter (column
;   i of w comes from letter column i * 32 / w). Its back is the other set of
;   letters, with the columns in the other order, so it reads mirrored.
;
;   PULSE: one transfer per row on the screen. The screen is column by column,
;   so the pixels of a row are 256 bytes apart: a transfer with a row length
;   of 1 and 32 rows, port B stride 256 (the X,Y form sets it) and port A
;   stride 32 (the letter's next column) copies one row of a letter. A taller
;   letter repeats rows, a shorter one leaves some out (row j of h comes from
;   letter row j * 32 / h).
;
; Each transfer is 10 bytes from the CPU: the source (WR0), the X,Y form of
; $DF, then $CF $87. Everything else is set once a frame. The worst frame,
; with about 250 of these plus the strip of background, takes 8.4ms for FLIP
; and 10.0ms for PULSE: about half of a 50Hz frame (issue 5, 28MHz).
;
; How the rest works:
;   - The two sets of letters are made by the CPU at the start: the 8x8 font
;     made 4 times bigger, coloured down the letter. Front: a rainbow, in
;     bank 28 ($0B0000). Back: metal, in bank 32 ($0C0000). Each letter is
;     1K, column by column, $E3 where there is no ink.
;   - Double buffered, as in zxnddma_sprites.asm: two screens, A (bank 9)
;     and B (bank 14), and a clean background in bank 20. Each frame, on the
;     screen not shown: copy the strip of background the letters use back over
;     it (one transfer), then draw the letters, skipping $E3.
;   - A clip window hides 32 pixels at each side. Letters are only drawn
;     when the whole 32-pixel slot is on the screen, so they slide in and out
;     under the clip and need no clipping of their own.
;
; Things to know:
;   - 16K bank n is at physical address $40000 + n * $4000, and 8K page n at
;     $40000 + n * $2000.
;   - In 320x256 the clip X values count 2 pixels.
; =============================================================================

    opt --zxnext
    device zxspectrumnext

DMA         equ $6B             ; zxnDDMA only answers on port $6B

SCREEN_A    equ 9               ; 16K banks
SCREEN_B    equ 14
BACKGROUND  equ 20
FRONT       equ 28              ; the letters, front
BACK        equ 32              ; the letters, back

SCREEN_A_AT equ $40000+SCREEN_A*$4000      ; $064000
SCREEN_B_AT equ $40000+SCREEN_B*$4000      ; $078000
BACK_AT     equ $40000+BACKGROUND*$4000    ; $090000
FRONT_AT    equ $40000+FRONT*$4000         ; $0B0000
METAL_AT    equ $40000+BACK*$4000          ; $0C0000

SLOT        equ 36              ; a letter and its gap
SPEED       equ 2               ; pixels a frame
BAND_Y      equ 104             ; the strip the letters use: 104 to 151
BAND_H      equ 48
MIDDLE      equ 128             ; the letters are centred on this line
FLIP_Y      equ MIDDLE-16
EFFECT_TIME equ 512             ; frames each effect lasts (power of 2)

LABEL_X     equ 40
LABEL_Y     equ 200

; $DF mode flags
PHYSICAL    equ %00000001       ; 24-bit physical addresses, no paging
TWO_D       equ %00000010       ; rows, with a stride on each side
TRANSPARENT equ %00000100       ; don't write the transparent byte ($F3)
FILL        equ %00001000       ; write the fill value ($F7), read nothing
XY          equ %00010000       ; Layer 2 X,Y destination follows
HIDDEN      equ %00100000       ; with XY: the screen in NextReg $13

LETTER      equ PHYSICAL|TWO_D|TRANSPARENT|XY|HIDDEN

    macro BOX x,y,w,h,colour    ; a box: x, y, width, height, colour
        dw x
        db y
        dw w,h
        db colour
    endm

    org $8000

start:
    nop                         ; four spare bytes, so a debugger's "go"
    nop                         ; can start here too
    nop
    nop
    di
    ld sp,$BFFE

    nextreg $07,3               ; 28MHz
    nextreg $CC,0               ; no interrupt may hold the DMA back
    nextreg $CD,0               ; (see zxnddma.gde, 2.9 note 10)
    nextreg $CE,0
    nextreg $54,4               ; this program: bank 2 in slots 4 and 5
    nextreg $55,5
    nextreg $69,0               ; Layer 2 off while we set up
    nextreg $70,%00010000       ; Layer 2 320x256
    nextreg $16,0               ; no Layer 2 scroll: an earlier program
    nextreg $71,0               ; may have left one
    nextreg $17,0
    nextreg $14,$E3             ; the transparent colour: $E3
    nextreg $4A,0               ; black behind everything
    nextreg $68,%10000000       ; ULA off
    nextreg $6B,0               ; tilemap off
    nextreg $43,%00010000       ; Layer 2 colours: the standard 256, where
    nextreg $40,0               ; colour n is RRRGGGBB = n. Another program
    xor a                       ; may have changed them.
.palette:
    nextreg $44,a               ; RRRGGGBB
    ld b,a
    srl a                       ; then blue's 9th bit: B1 or B0
    or b
    and 1
    nextreg $44,a
    ld a,b
    inc a
    jr nz,.palette
    nextreg $1C,1               ; clip window: hide 32 pixels each side
    nextreg $18,16              ;   X1: pixel 32
    nextreg $18,143             ;   X2: pixel 287
    nextreg $18,0
    nextreg $18,255
    nextreg $15,0               ; Layer 2 above the ULA, sprites off

    ld a,FRONT*2                ; the two sets of big letters
    ld hl,front_colours
    call make_letters
    ld a,BACK*2
    ld hl,back_colours
    call make_letters

    nextreg $12,BACKGROUND      ; the background, in bank 20
    call draw_background
    ld a,SCREEN_A_AT>>16        ; copied to both screens
    ld hl,SCREEN_A_AT&$FFFF
    call copy_background
    ld a,SCREEN_B_AT>>16
    ld hl,SCREEN_B_AT&$FFFF
    call copy_background
    call show_label

    nextreg $12,SCREEN_A        ; shown
    nextreg $13,SCREEN_B        ; drawn
    nextreg $69,%10000000       ; Layer 2 on

frame:
    call wait_bottom
    call swap_screens
    call rub_out
    call draw_letters
    call next_frame
    jr frame

; -----------------------------------------------------------------------------
; Wait for line 224, just below the bottom of the 320x256 picture
; -----------------------------------------------------------------------------
wait_bottom:
    ld bc,$243B                 ; select NextReg $1F, the video line
    ld a,$1F
    out (c),a
    inc b                       ; read it at $253B
.out:
    in a,(c)                    ; if we are on line 224 already, let it end
    cp 224
    jr z,.out
.in:
    in a,(c)
    cp 224
    jr nz,.in
    ret

; -----------------------------------------------------------------------------
; Show the screen we have just drawn, and draw on the other one
; -----------------------------------------------------------------------------
swap_screens:
    ld a,(shown)
    ld b,a
    ld a,(drawn)
    ld (shown),a
    nextreg $12,a
    ld a,b
    ld (drawn),a
    nextreg $13,a
    ld hl,(state_shown)         ; and swap the notes of what each shows
    ld de,(state_drawn)
    ld (state_shown),de
    ld (state_drawn),hl
    ret

shown:
    db SCREEN_A
drawn:
    db SCREEN_B
state_shown:
    dw state_a
state_drawn:
    dw state_b
state_a:
    ds 5                        ; frame (2 bytes), offset, first letter,
state_b:                        ; effect: what was drawn on each screen
    ds 5

; -----------------------------------------------------------------------------
; Put the background back over the strip the letters use: one transfer
; -----------------------------------------------------------------------------
rub_out:
    ld hl,rub_dma
    ld bc,(rub_dma_end-rub_dma)*256+DMA
    otir
    ret

rub_dma:
    db $83,$C3                  ; stop, reset
    db $54,$02                  ; WR1: memory, increment, 2-cycle timing
    db $50,$02                  ; WR2: memory, increment, 2-cycle timing
                                ; (checked on issue 5; if a board shows
                                ; wrong pixels, use $14,$10 for the default)
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3 : dw BAND_H          ; row length: the strip's height
    db $E7 : dw 320             ; rows: the whole width
    db $EB : dw 256             ; port A stride: the background's next column
    db $1D                      ; WR0: A to B, port A address: the strip in
    dw (BACK_AT&$FFFF)+BAND_Y   ; the background
    db $D7,BACK_AT>>16
    db $DF,PHYSICAL|TWO_D|XY|HIDDEN
    dw 0
    db BAND_Y
    db $CF,$87                  ; load, go
rub_dma_end:

; -----------------------------------------------------------------------------
; Draw the letters that are wholly on the screen, from x = -offset, a slot
; (36 pixels) apart
; -----------------------------------------------------------------------------
draw_letters:
    ld hl,(state_drawn)         ; note what this screen is about to show
    ex de,hl
    ld hl,frame_count
    ld bc,5
    ldir

    ld a,(effect)               ; this effect's sizes
    or a
    ld hl,flip_setup
    ld bc,(flip_setup_end-flip_setup)*256+DMA
    jr z,.setup
    ld hl,pulse_setup
    ld bc,(pulse_setup_end-pulse_setup)*256+DMA
.setup:
    otir

    ld a,(first)
    ld (letter),a
    ld a,(offset)               ; x = -offset
    neg
    ld l,a
    sbc a,a
    ld h,a
.next:
    bit 7,h                     ; still off the left? skip this one
    jr nz,.skip
    push hl
    ld de,-(320-32+1)           ; past 288: done
    add hl,de
    pop hl
    ret c
    ld (letter_x),hl
    call draw_one_letter
    ld hl,(letter_x)
.skip:
    ld de,SLOT
    add hl,de
    ld a,(letter)               ; next letter of the message
    inc a
    cp message_end-message
    jr c,.letter
    xor a
.letter:
    ld (letter),a
    jr .next

; Draw message letter (letter) at letter_x, with this frame's effect
draw_one_letter:
    ld a,(letter)               ; the glyph: character - 32
    ld e,a
    ld d,0
    ld hl,message
    add hl,de
    ld a,(hl)
    sub 32
    ld h,a                      ; HL = glyph * 1024: bits 15:0 of where the
    ld l,0                      ; letter starts (both sets start at $..0000)
    add hl,hl
    add hl,hl
    ld (glyph_at),hl

    ld a,(frame_count)          ; its angle: frame * 3 + letter * 20
    ld b,a
    add a,a
    add a,b
    ld b,a
    ld a,(letter)
    ld c,a
    add a,a
    add a,a
    add a,c                     ; letter * 5
    add a,a
    add a,a                     ; letter * 20
    add a,b
    ld (angle),a

    ld a,(effect)
    or a
    jp nz,pulse_letter
    ; fall through into flip_letter

; -----------------------------------------------------------------------------
; FLIP: one transfer per screen column. Width = 32 * |cos angle|; the back
; (cos < 0) comes from the metal letters, columns in the other order.
; -----------------------------------------------------------------------------
flip_letter:
    ld a,(angle)                ; cos = sin(angle + 64)
    add a,64
    call sine
    ld c,FRONT_AT>>16           ; front, or back?
    bit 7,a
    jr z,.front
    neg
    ld c,METAL_AT>>16
.front:
    add a,2                     ; width = (|cos| + 2) / 4: 0 to 32
    srl a
    srl a
    ret z                       ; edge on: nothing to draw
    ld (width),a
    ld a,c
    ld (flip_hi),a
    ld (back_side),a

    ld hl,flip_hi_dma           ; which set: port A bits 23:16
    ld bc,2*256+DMA
    otir

    ld a,(width)                ; step through the letter: 32 / width
    call step_for
    ld (step),hl
    ld a,(width)                ; x = slot x + 16 - width / 2
    srl a
    ld e,a
    ld d,0
    ld hl,(letter_x)
    ld bc,16
    add hl,bc
    or a
    sbc hl,de
    ld (col_x),hl
    ld hl,0                     ; position in the letter, 8.8
    ld (along),hl
    ld a,(width)
    ld b,a
.column:
    push bc
    ld a,(along+1)              ; letter column = along / 256
    ld e,a
    ld a,(back_side)            ; the back reads the other way
    cp FRONT_AT>>16
    ld a,e
    jr z,.this_way
    cpl                         ; 31 - column
    and 31
.this_way:
    ld l,a                      ; source = glyph + column * 32
    ld h,0
    add hl,hl
    add hl,hl
    add hl,hl
    add hl,hl
    add hl,hl
    ld de,(glyph_at)
    add hl,de
    ld (one_from),hl
    ld hl,(col_x)
    ld (one_x),hl
    inc hl
    ld (col_x),hl
    ld a,FLIP_Y
    ld (one_y),a
    ld hl,one_dma
    ld bc,(one_dma_end-one_dma)*256+DMA
    otir
    ld hl,(along)
    ld de,(step)
    add hl,de
    ld (along),hl
    pop bc
    djnz .column
    ret

flip_hi_dma:
    db $D7
flip_hi:
    db 0

; -----------------------------------------------------------------------------
; PULSE: one transfer per screen row. Height = 32 + sin(angle) / 8: 16 to 48
; -----------------------------------------------------------------------------
pulse_letter:
    ld a,(angle)
    call sine
    sra a                       ; / 8: -16 to 15
    sra a
    sra a
    add a,32
    ld (height),a
    call step_for               ; step through the letter: 32 / height
    ld (step),hl
    ld a,(height)               ; y = middle - height / 2
    srl a
    ld b,a
    ld a,MIDDLE
    sub b
    ld (row_y),a
    ld hl,(letter_x)
    ld (one_x),hl
    ld hl,0
    ld (along),hl
    ld a,(height)
    ld b,a
.row:
    push bc
    ld a,(along+1)              ; letter row = along / 256
    ld e,a
    ld d,0
    ld hl,(glyph_at)            ; source = glyph + row
    add hl,de
    ld (one_from),hl
    ld a,(row_y)
    ld (one_y),a
    inc a
    ld (row_y),a
    ld hl,one_dma
    ld bc,(one_dma_end-one_dma)*256+DMA
    otir
    ld hl,(along)
    ld de,(step)
    add hl,de
    ld (along),hl
    pop bc
    djnz .row
    ret

; One column (FLIP) or one row (PULSE) of a letter: 10 bytes
one_dma:
    db $1D                      ; WR0: A to B, port A address
one_from:
    dw 0
    db $DF,LETTER               ; X,Y on the hidden screen, skip $E3
one_x:
    dw 0
one_y:
    db 0
    db $CF,$87                  ; load, go
one_dma_end:

flip_setup:                     ; FLIP: a transfer is one column of 32
    db $E3 : dw 32              ; row length: 32 (down the column)
    db $E7 : dw 1               ; rows: 1
    db $EB : dw 32
    db $F3,$E3                  ; transparent byte
flip_setup_end:

pulse_setup:                    ; PULSE: a transfer is one row of 32
    db $E3 : dw 1               ; row length: 1 (one pixel)
    db $E7 : dw 32              ; rows: 32, 256 bytes apart on the screen
    db $EB : dw 32              ; port A stride: the letter's next column
    db $F3,$E3                  ; transparent byte
    db $D7,FRONT_AT>>16         ; port A bits 23:16: the front letters
pulse_setup_end:

; A = sin(A) (A in 256ths of a turn), -127 to 127
sine:
    ld e,a
    ld d,0
    ld hl,sine_table
    add hl,de
    ld a,(hl)
    ret

; HL = 32 * 256 / A: the step through a 32-pixel letter for A pixels (A 1-48)
step_for:
    add a,a
    ld e,a
    ld d,0
    ld hl,steps
    add hl,de
    ld a,(hl)
    inc hl
    ld h,(hl)
    ld l,a
    ret

steps:
N = 0
    dup 49
    if N = 0
    dw 0
    else
    dw 32*256/N
    endif
N = N+1
    edup

; -----------------------------------------------------------------------------
; On to the next frame: scroll, and change effect every EFFECT_TIME frames
; -----------------------------------------------------------------------------
next_frame:
    ld hl,(frame_count)
    inc hl
    ld (frame_count),hl
    ld a,(offset)               ; scroll SPEED pixels
    add a,SPEED
    cp SLOT
    jr c,.offset
    sub SLOT                    ; a whole slot: on to the next letter
    ld b,a
    ld a,(first)
    inc a
    cp message_end-message
    jr c,.first
    xor a
.first:
    ld (first),a
    ld a,b
.offset:
    ld (offset),a
    ld a,l                      ; time to change effect?
    and low (EFFECT_TIME-1)
    ret nz
    ld a,h
    and high (EFFECT_TIME-1)
    ret nz
    ld a,(effect)
    xor 1
    ld (effect),a
    jp show_label

frame_count:                    ; (these five are copied into the notes)
    dw 0
offset:
    db 0                        ; how far the first letter is off the left
first:
    db 0                        ; the first letter's place in the message
effect:
    db 0                        ; 0 = FLIP, 1 = PULSE

letter:     db 0
letter_x:   dw 0
glyph_at:   dw 0
angle:      db 0
width:      db 0
height:     db 0
back_side:  db 0
step:       dw 0
along:      dw 0
col_x:      dw 0
row_y:      db 0

message:
    db "ZXNDDMA ON THE ZX SPECTRUM NEXT ...  BIG LETTERS, DRAWN A COLUMN AT "
    db "A TIME TO FLIP THEM, OR A ROW AT A TIME TO MAKE THEM PULSE ...  "
    db "EVERY COLUMN OR ROW IS ONE DMA TRANSFER, STRAIGHT FROM A FONT IN "
    db "HIGH MEMORY ...  TEN BYTES FROM THE CPU EACH ...          "
message_end:
    assert message_end-message < 256

; -----------------------------------------------------------------------------
; Make a set of 64 big letters: the 8x8 font, each pixel made 4x4, coloured
; down the letter from a table of 32 colours. Each letter is 32 columns of 32
; bytes, $E3 where there is no ink, 8 letters to an 8K page.
; In: A = the set's first 8K page, HL -> its 32 colours
; -----------------------------------------------------------------------------
make_letters:
    ld (ml_page),a
    ld (ml_colours),hl
    xor a
    ld (ml_glyph),a
.glyph:
    ld a,(ml_glyph)             ; page: first + glyph / 8
    rrca
    rrca
    rrca
    and 7
    ld hl,ml_page
    add a,(hl)
    nextreg $56,a               ; in slot 6
    ld a,(ml_glyph)             ; at $C000 + (glyph mod 8) * 1024
    and 7
    add a,a
    add a,a
    add a,$C0
    ld d,a
    ld e,0
    ld a,(ml_glyph)             ; the font's 8 bytes for it
    ld l,a
    ld h,0
    add hl,hl
    add hl,hl
    add hl,hl
    ld bc,font
    add hl,bc
    ld (ml_font),hl
    ld c,$80                    ; C = the font column's bit
    ld b,32                     ; 32 columns
.column:
    ld ix,(ml_colours)
    ld iy,(ml_font)
    ld l,8                      ; 8 font rows ...
.font_row:
    ld h,4                      ; ... of 4 rows each
.row:
    ld a,(iy+0)
    and c
    ld a,$E3                    ; no ink
    jr z,.put
    ld a,(ix+0)                 ; ink: this row's colour
.put:
    ld (de),a
    inc de
    inc ix
    dec h
    jr nz,.row
    inc iy
    dec l
    jr nz,.font_row
    ld a,b                      ; every 4 columns, the next font column
    dec a
    and 3
    jr nz,.same
    srl c
.same:
    djnz .column
    ld a,(ml_glyph)
    inc a
    ld (ml_glyph),a
    cp 64
    jr nz,.glyph
    ret

ml_page:    db 0
ml_colours: dw 0
ml_glyph:   db 0
ml_font:    dw 0

front_colours:
    db $E0,$E4,$E4,$E8,$EC,$EC,$F0,$F4,$F4,$F8,$D8,$B8,$9C,$7C,$7C,$5C
    db $3D,$1D,$1D,$1A,$1A,$1A,$17,$13,$33,$2F,$4B,$4B,$67,$87,$83,$A3
back_colours:
    db $FF,$FF,$FF,$DB,$DB,$DB,$B7,$B6,$92,$92,$92,$92,$6E,$6E,$6E,$6E
    db $4B,$4B,$4B,$6F,$73,$73,$97,$97,$B7,$BB,$DB,$DB,$B7,$92,$92,$6E

; -----------------------------------------------------------------------------
; The background, in the screen in NextReg $12 (the background bank): a glow
; behind the letters, two lines round their strip, a title and a black panel
; for the name of the effect
; -----------------------------------------------------------------------------
draw_background:
    ld hl,glow                  ; 32 stripes of 8 lines
    ld (glow_at),hl
    xor a
.stripe:
    ld (stripe_y),a
    ld hl,(glow_at)
    ld a,(hl)
    inc hl
    ld (glow_at),hl
    ld (stripe+7),a
    ld a,(stripe_y)
    ld (stripe+2),a
    ld ix,stripe
    ld b,1
    call boxes
    ld a,(stripe_y)
    add a,8
    jr nz,.stripe

    ld ix,background
    ld b,(background_end-background)/8
    call boxes

    ld a,BACKGROUND*2           ; the title
    ld (print_page),a
    ld a,$FF
    ld (ink),a
    ld ix,title
    ld hl,108
    ld e,40
    jp print

glow:
    db $00,$00,$01,$01,$02,$02,$22,$22,$23,$23,$43,$43,$42,$42,$62,$62
    db $62,$62,$42,$42,$43,$43,$23,$23,$22,$22,$02,$02,$01,$01,$00,$00
glow_at:
    dw 0
stripe_y:
    db 0
stripe:
    BOX 0,0,320,8,0

background:
    BOX 0,BAND_Y-4,320,2,$FC            ; a line above the letters
    BOX 0,BAND_Y+BAND_H+2,320,2,$FC     ; and one below
    BOX 32,192,256,24,$00               ; the panel for the effect's name
background_end:

title:
    db "ZXNDDMA SCROLLER",0

; -----------------------------------------------------------------------------
; Write the effect's name on the panel, on all three: the background and both
; screens. The panel is cleared with a fill to a physical address (not X,Y,
; which would mean pointing NextReg $12 away from the screen on show).
; -----------------------------------------------------------------------------
show_label:
    ld hl,label_banks
    ld b,3
.bank:
    push bc
    ld a,(hl)                   ; 16K bank
    inc hl
    push hl
    ld (label_bank),a
    add a,a                     ; for the text: its first 8K page
    ld (print_page),a
    ld a,(label_bank)           ; physical address of the panel:
    ld l,a                      ; $40000 + bank * $4000 + 32 * 256 + 192
    ld h,0
    ld de,16                    ; (bank + 16) * $4000 = (bank + 16) << 14
    add hl,de
    ld a,l                      ; bits 23:16 = (bank + 16) >> 2
    srl a
    srl a
    ld (panel_hi),a
    ld a,l                      ; bits 15:14 = (bank + 16) & 3
    and 3
    rrca
    rrca
    or high (32*256+192)
    ld (panel_at+1),a
    ld a,low (32*256+192)
    ld (panel_at),a
    ld hl,panel_dma
    ld bc,(panel_dma_end-panel_dma)*256+DMA
    otir

    ld a,$FF
    ld (ink),a
    ld a,(effect)
    or a
    ld ix,flip_name
    jr z,.name
    ld ix,pulse_name
.name:
    ld hl,LABEL_X
    ld e,LABEL_Y
    call print
    pop hl
    pop bc
    djnz .bank
    ret

label_banks:
    db BACKGROUND,SCREEN_A,SCREEN_B
label_bank:
    db 0

panel_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
panel_at:
    dw 0
    db $82                      ; WR5: stop at the end
    db $DB                      ; port B bits 23:16
panel_hi:
    db 0
    db $E3 : dw 24              ; row length: the panel's height
    db $E7 : dw 256             ; rows: its width
    db $EF : dw 256             ; port B stride: the next column
    db $F7,0                    ; fill value: black
    db $DF,PHYSICAL|TWO_D|FILL
    db $CF,$87                  ; load, go
panel_dma_end:

flip_name:
    db "FLIP: ONE COLUMN AT A TIME",0
pulse_name:
    db "PULSE: ONE ROW AT A TIME",0

; -----------------------------------------------------------------------------
; Boxes, drawn with fill mode at X,Y on the screen in NextReg $12
; -----------------------------------------------------------------------------

; Draw B boxes from the list at IX
boxes:
    push bc
    ld l,(ix+0)
    ld h,(ix+1)
    ld (box_x),hl
    ld a,(ix+2)
    ld (box_y),a
    ld l,(ix+3)                 ; rows = width
    ld h,(ix+4)
    ld (box_w),hl
    ld l,(ix+5)                 ; row length = height
    ld h,(ix+6)
    ld (box_h),hl
    ld a,(ix+7)
    ld (box_colour),a
    ld hl,box_dma
    ld bc,(box_dma_end-box_dma)*256+DMA
    otir
    ld de,8
    add ix,de
    pop bc
    djnz boxes
    ret

box_dma:
    db $83,$C3                  ; stop, reset
    db $05                      ; WR0: A to B
    db $14,$10                  ; WR1, WR2: memory, increment
    db $A1                      ; WR4: continuous, no address (X,Y gives it)
    db $82                      ; WR5: stop at the end
    db $E3                      ; row length: the height
box_h:
    dw 0
    db $E7                      ; rows: the width
box_w:
    dw 0
    db $F7                      ; fill value: the colour
box_colour:
    db 0
    db $DF,PHYSICAL|TWO_D|FILL|XY
box_x:
    dw 0
box_y:
    db 0
    db $CF,$87                  ; load, go
box_dma_end:

; Copy the whole background (80K) to a screen
; In: A = screen address bits 23:16, HL = bits 15:0
copy_background:
    ld (copy_to_hi),a
    ld (copy_to),hl
    ld hl,copy_dma
    ld bc,(copy_dma_end-copy_dma)*256+DMA
    otir
    ret

copy_dma:
    db $83,$C3                  ; stop, reset
    db $7D                      ; WR0: A to B, port A address, length
    dw BACK_AT&$FFFF
    dw 0                        ;   length: not used in 2D
    db $14,$10                  ; WR1, WR2: memory, increment
    db $AD                      ; WR4: continuous, port B address follows
copy_to:
    dw 0
    db $82                      ; WR5: stop at the end
    db $D7,BACK_AT>>16          ; port A bits 23:16
    db $DB                      ; port B bits 23:16
copy_to_hi:
    db 0
    db $E3 : dw 16384           ; 5 rows of 16K: 80K in one go
    db $E7 : dw 5
    db $EB : dw 16384
    db $EF : dw 16384
    db $DF,PHYSICAL|TWO_D
    db $CF,$87                  ; load, go
copy_dma_end:

; -----------------------------------------------------------------------------
; Small text, drawn by the CPU with the 1-bit 8x8 font
; -----------------------------------------------------------------------------

; Print the text at IX (ends with 0) at HL = x, E = y, in colour ink, on the
; Layer 2 screen whose first 8K page is print_page
print:
    ld a,(ix+0)
    or a
    ret z
    push hl
    push de
    call print_char
    pop de
    pop hl
    ld bc,8
    add hl,bc
    inc ix
    jr print

print_char:
    ld (char),a
    call map_xy                 ; HL = screen
    ld a,(char)
    sub 32
    push hl
    ld l,a                      ; DE = the letter's 8 bytes
    ld h,0
    add hl,hl
    add hl,hl
    add hl,hl
    ld de,font
    add hl,de
    ex de,hl
    pop hl
    ld c,$80                    ; C = this column's bit
.col:
    push hl
    push de
    ld b,8
.row:
    ld a,(de)
    and c
    jr z,.blank
    ld a,(ink)
    ld (hl),a
.blank:
    inc de
    inc l
    djnz .row
    pop de
    pop hl
    inc h                       ; next column
    srl c
    jr nc,.col                  ; after 8 columns the bit drops out
    ret

; Page the screen at x into MMU slots 6 and 7, and point at x,y.
; In: HL = x, E = y. Out: HL = the CPU address of x,y (in $C000-$FFFF).
map_xy:
    ld a,l                      ; high byte: $C0 + (x mod 32)
    and 31
    add a,$C0
    ld d,a
    ld a,l                      ; page: first page + x / 32
    and $E0
    or h
    rlca
    rlca
    rlca
    ld hl,print_page
    add a,(hl)
    nextreg $56,a
    inc a
    nextreg $57,a
    ex de,hl                    ; HL = address, E was y
    ret

print_page:
    db 0
ink:
    db 0
char:
    db 0

; sin(n / 256 of a turn) * 127, signed

    db 117,118,120,121,122,122,123,124,125,125,126,126,126,127,127,127
    db 127,127,127,127,126,126,126,125,125,124,123,122,122,121,120,118
    db 117,116,115,113,112,111,109,107,106,104,102,100,98,96,94,92
